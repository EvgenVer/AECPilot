# specs/docgen — Генерация черновиков документов (skill aec-docgen)
<!-- Behavior contract for ONE feature. References SPECIFICATION, never copies it. -->

## Overview & requirement link
Ref: SPECIFICATION.md — G3; AC4; N2.
Решение владельца (grill 06.07.2026, уточнено): целевой тип MVP — **пояснительная записка** (разделы ПЗ). Механика шаблонная: движок один, типы документов = шаблоны, поэтому реестр расширяется новыми шаблонами без изменения этой спеки.

## Behavior (BDD / Gherkin)
Scenario: Черновик раздела ПЗ по шаблону
  Given в vault/templates/<name>/ лежит DOCX-шаблон организации с плейсхолдерами {{field}} и manifest.yaml
  And источники проиндексированы (и, опционально, вики построена)
  When пользователь командует «подготовь черновик ПЗ раздела X»
  Then агент собирает значения полей из вики/источников (через rag_query)
  And заполняет шаблон и сохраняет в workspace/drafts/ (DOCX + отчёт .report.md)
  And отчёт перечисляет: каждое заполненное поле → откуда взято [src:…]; каждое незаполненное → причина
  And результат — черновик для человека; наружу ничего не отправляется

Scenario: Данных не хватает (анти-галлюцинация)
  Given для required-поля данных в источниках нет
  Then плейсхолдер остаётся маркированным «⚠ НЕ НАЙДЕНО»
  And поле попадает в список недостающего в отчёте
  And агент не выдумывает значение

Scenario: Конфликтующие данные для поля
  Given две редакции задания дают разные значения поля
  Then поле помечается «конфликт», обе версии с [src:…] — в отчёте (синергия с aec-id-check)

Scenario: Шаблон отсутствует
  When запрошен тип документа без шаблона в templates/
  Then понятная ошибка + подсказка со структурой шаблона и примером manifest

## Data schemas
```
templates/<name>/
  template.docx    # DOCX с плейсхолдерами {{field}}
  manifest.yaml    # - field: power_installed
                   #   description: "Установленная мощность, кВт"
                   #   source_hint: "задание ЭОМ, таблица нагрузок"
                   #   required: true
```
Выход: `workspace/drafts/<name>-<date>.docx` + `<name>-<date>.report.md`.

## API contracts
Использует `aec-rag` и вики; запись — только в vault (workspace/drafts/). Рендер DOCX — библиотека docxtpl (PLAN §Dependencies). Отдельный MCP не требуется.

## Edge cases
- Табличные плейсхолдеры (перечни строк) — в MVP-версии скилла не поддерживаются: скалярные поля и простые списки; таблицы — пометка в отчёте (расширение после MVP).
- Шаблон со стилями/колонтитулами → рендер сохраняет форматирование DOCX (ответственность docxtpl; проверяется тестом).
- Язык: текст значений — на языке шаблона.

## Feature-level acceptance & validation
- Детерминированное (pytest): парсер manifest, рендер шаблона (подстановка, сохранение стилей), маркировка «НЕ НАЙДЕНО».
- Smoke-эвал ≥5 сценариев (AC4): референс-шаблон ПЗ (~10 полей) на фикстурном мини-проекте. Метрики: заполнены все находимые поля; **0 выдуманных значений** (каждое заполненное поле имеет валидный [src:…]); незаполненные корректно помечены; конфликт оформлен по сценарию. Прогон при изменении промпта/модели.
