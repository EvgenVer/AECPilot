# specs/workspace-sources — Проект (vault) и read-only источники
<!-- Behavior contract for ONE feature. References SPECIFICATION, never copies it. -->

## Overview & requirement link
Ref: SPECIFICATION.md — UR1, UR2, UR7, UR8; AC5, AC6; N3; C4.
Контракт фундамента: рабочая папка проекта (vault), подключаемые read-only источники, файловый индекс и детект изменений.

## Behavior (BDD / Gherkin)
Scenario: Создание проекта в пустой директории
  Given пользователь выбрал пустую директорию D
  When он создаёт проект «Объект-X»
  Then в D создаётся структура vault (см. Data schemas)
  And проект появляется в списке недавних и открывается

Scenario: Инициализация проекта в непустой директории (Obsidian-style)
  Given пользователь выбрал директорию D, в которой уже есть его файлы/папки
  And в D нет каталога .aecpilot (D ещё не проект AECPilot)
  When он инициализирует проект «Объект-X» в D
  Then недостающие служебные элементы структуры vault создаются (wiki/, workspace/, templates/, .aecpilot/, AGENTS.md)
  And уже существующие файлы и папки пользователя не изменяются и не удаляются
  And если конфликтует служебное имя (в D уже есть свой AGENTS.md либо .aecpilot) — приложение спрашивает подтверждение и по умолчанию НЕ перезаписывает
  And проект появляется в списке недавних и открывается

Scenario: Открытие существующего проекта
  Given директория D уже содержит .aecpilot/project.json
  When пользователь открывает D
  Then проект открывается без повторной инициализации структуры

Scenario: Подключение источника
  Given открыт проект
  When пользователь добавляет источник с путём \\server\tasks\object-x
  Then источник появляется в дереве проводника с пометкой read-only
  And его файлы и подпапки доступны для навигации и просмотра (дерево разворачивается на любую глубину, как у vault)
  And запись об источнике сохранена в конфиге проекта

Scenario: Открытие в системном проводнике
  Given в дереве выбран узел (папка или файл, vault или источника)
  When пользователь выбирает в контекстном меню «Показать в проводнике»
  Then открывается системный файловый менеджер с этим путём (файл — подсвечен в родительской папке)
  And содержимое vault и источников при этом не изменяется

Scenario: Гарантия read-only (негативный)
  Given агенту доступны инструменты работы с источниками
  When агент вызывает операцию записи/удаления по пути внутри источника
  Then операция отклоняется с ошибкой READ_ONLY_SOURCE (write-операций для источников не существует в инструментальном слое)
  And попытка фиксируется в журнале проекта

Scenario: Недоступный источник
  Given источник на сетевом диске подключён и проиндексирован
  When сетевой путь становится недоступен
  Then дерево показывает у источника статус «недоступен»
  And остальные функции проекта продолжают работать
  And поиск по существующему индексу работает с пометкой «индекс может быть устаревшим»

Scenario: Детект изменений
  Given источник проиндексирован (для файлов сохранены SHA256)
  When файл в источнике изменён/добавлен/удалён и прошёл цикл сканирования
  Then приложение показывает уведомление со списком изменений
  And предлагает действия (re-ingest выбранного, обновить вики)
  And без подтверждения пользователя индексы и файлы vault не меняются

Scenario: Отключение источника
  Given источник подключён и участвует в индексе
  When пользователь отключает источник
  Then файлы источника исчезают из дерева
  And связанные записи индекса помечаются как detached (не удаляются молча)
  And страницы вики со ссылками на этот источник остаются, с пометкой «источник отключён»

## API contracts
MCP-сервер `aec-sources` (инструменты агента; только чтение — write-операций нет by construction):
- `sources_list()` → `[{id, root_path, status: ok|unavailable}]`
- `sources_tree(source_id, path?)` → записи каталога (имя, тип, размер, mtime)
- `sources_read(source_id, path, range?)` → содержимое (текст или байты для парсера)
- `sources_stat(source_id, path)` → `{size, mtime, sha256?}`
Vault: агент работает штатными файловыми инструментами Hermes; working dir агента = vault.

UI-операции дерева (не MCP; Electron shell, только чтение ФС):
- Единое дерево-проводник: в активности «Проводник» vault и подключённые источники —
  секции ОДНОГО дерева (UR2, PLAN §Architecture), один паттерн разворачивания вглубь;
  источники помечены read-only (просмотр/навигация, без операций записи). Управление
  жизненным циклом источников (подключить/отключить, статус, предупреждения о
  пересечении) — в отдельной активности «Источники» рельсы (PLAN §Architecture),
  карточками; само дерево источников — в «Проводнике».
- «Показать в проводнике» — любой узел (папка/файл, vault или источника, на любом
  уровне вложенности) (`shell.showItemInFolder` / `shell.openPath`).
- «Копировать путь» — любой узел.
- «Открыть во внешнем приложении» — файлы (`shell.openPath`); для источников это не
  нарушает RO (открытие на чтение системным приложением).
- Контекстное меню (правый клик) на любом узле дублирует доступные для узла команды
  (создать файл/папку — для vault, переименовать, удалить, показать в проводнике,
  копировать путь, обновить); те же команды доступны иконками панели инструментов
  дерева. Удаление узла vault — также по клавише Del (в корзину, с подтверждением).
- Поле поиска/фильтра по дереву проводника (фильтрация видимых узлов по подстроке
  имени).

## Data schemas
Vault (создаётся при создании проекта):
```
<vault>/
  wiki/            # вики проекта (ведёт skill aec-wiki; структура — specs/wiki.md)
  workspace/       # рабочие файлы и артефакты агента/пользователя (reports/, drafts/)
  templates/       # DOCX-шаблоны документов + manifest (specs/docgen.md)
  AGENTS.md        # проектные правила для агента (генерируется из шаблона)
  .aecpilot/
    project.json   # {name, created_at, sources: [{id, root_path, added_at}],
                   #  settings: {wiki_lang: "auto"|<code>, scan_interval_s, embedding_model}}
    index.db       # SQLite: files(source_id, rel_path, size, mtime, sha256,
                   #   status: ok|changed|deleted|detached, skip_reason: too_large|unreadable|NULL,
                   #   indexed_at) + FTS5 по извлечённому тексту
    lancedb/       # векторное хранилище (появляется в Phase 2)
    memory/        # память проекта Mem0 (появляется в Phase 5, specs/agent-memory.md)
    logs/          # журнал операций и отклонённых попыток записи
```

## Edge cases
- UNC-пути, кириллица и пробелы в путях (Windows) — обязательные тестовые фикстуры.
- Длинные пути (>260 символов) — long-path поддержка либо понятная ошибка.
- Файл заблокирован (открыт в Word/Excel) — чтение теневой копией или пропуск с пометкой; без падения.
- Файл больше лимита (настройка, default 200 МБ) — пропуск с пометкой в индексе.
- Циклы symlink/junction — защита обходчика (учёт посещённых путей).
- Junction, ведущий ЗА корень источника, обходчик проходит, и это решение, а не
  недосмотр (находка D-52, решено владельцем 2026-08-26). Корень источника —
  не граница удержания: junction внутри подключённой папки считается её частью.
  Замер 2026-08-26: настоящие symlink (и на файл, и на папку) обходчик выбрасывает,
  а junction — нет, потому что на Windows это единственный вид ссылки, который
  Python ссылкой не считает (`os.path.islink` даёт `False`). Следствие, записанное
  здесь, чтобы его не открывали заново: содержимое за таким junction разбирается,
  режется на куски и уезжает в провайдер embeddings наравне с файлами источника.
  Разбор допущения и повод к нему вернуться — `docs/SECURITY.md`, §Accepted risks.
- Источник внутри vault или vault внутри источника — запрещено при добавлении (валидация).
- Пересекающиеся пути двух источников — предупреждение пользователю.
- Инициализация проекта в непустой папке: существующие файлы/папки пользователя
  неприкосновенны; конфликт служебного имени (свой AGENTS.md/.aecpilot уже есть) →
  подтверждение, по умолчанию без перезаписи.

## Feature-level acceptance & validation
- pytest: индексер (sha256, статусы, детект add/change/delete), негативные тесты read-only, обходчик (все edge cases выше — фикстурами).
- Интеграционный тест: mock-источник → цикл «подключить → сканировать → изменить файл → уведомление».
- Ручной чек-лист по BDD-сценариям на реальной сетевой шаре (Windows).
- Эвалы не требуются: поведение детерминированное.
