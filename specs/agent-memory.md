## Overview & requirement link
Ref: SPECIFICATION.md — G4; DESCRIPTION (слои знаний: память = решения/предпочтения/уроки сквозь сессии).
Решение владельца (grill 06.07.2026): автоматическое извлечение фактов + полная видимость и управление в UI. Запись памяти не считается «изменением артефактов» (решение №11 про vault/индексы/вики) и не требует подтверждений.

## Behavior (BDD / Gherkin)
Scenario: Автозапись проектного факта
  Given идёт диалог в открытом проекте
  When в диалоге зафиксирован устойчивый проектный факт («заказчик просил закладывать резерв мощности 20%»)
  Then память project-scope пополняется фактом (автоизвлечение Mem0)
  And факт виден в журнале памяти UI с датой и сессией-источником

Scenario: Автозапись пользовательского предпочтения
  When факт касается пользователя, а не проекта («я веду раздел ОВ», «отвечай короче»)
  Then он сохраняется в user-scope и действует во всех проектах

Scenario: Использование памяти (recall)
  Given в памяти есть релевантные текущей задаче факты
  When агент выполняет новый запрос
  Then релевантные факты учитываются (recall через инструмент + правило в проектном AGENTS.md)
  And ответ согласуется с ними (например, применяет резерв 20%)

Scenario: Управление памятью
  When пользователь открывает журнал памяти в UI
  Then он видит списки user- и project-фактов, может удалить любой факт
  And может отключить автозапись переключателем в настройках
  And удалённый факт больше не участвует в recall

Scenario: Фильтр секретов (негативный)
  Given в диалоге встречается строка, похожая на секрет (API-ключ, пароль, токен)
  Then автозапись её не сохраняет (паттерн-фильтр до Mem0.add)

Scenario: Локальность
  Then содержимое памяти хранится только локально (project — в .aecpilot/memory/, user — в профиле приложения) и не покидает машину, кроме штатных вызовов настроенного LLM-endpoint

## API contracts
MCP `aec-memory` (инструменты агента):
- `memory_add({scope: "user"|"project", text, meta?})`
- `memory_search({scope: "user"|"project"|"both", query, top_k?})` → `[{id, scope, text, created_at}]`
- `memory_list({scope, page?})`, `memory_delete({id})`
Автозапись: реализуется слоем AECPilot по событиям завершения обмена в gateway-сессии (не полагаясь на дисциплину модели), конфигурируемо (вкл/выкл). Recall в MVP: инструмент `memory_search` + правило в шаблоне проектного AGENTS.md («в начале задачи сверься с памятью»).

## Data schemas
- project-scope: `<vault>/.aecpilot/memory/` (Mem0: локальный vector store + history SQLite).
- user-scope: `<app-profile>/memory/`.
- Факт: `{id, scope, text, created_at, source_session, tags?}`.

## Edge cases
- Дубликат факта → консолидация Mem0 (update, не дубль).
- Противоречащий новый факт («резерв теперь 15%») → замена с сохранением истории; журнал отражает изменение.
- Автозапись отключена → пополнение только явной командой («запомни…» → memory_add).
- Проект закрыт/переключён → project-scope другого проекта недоступен.

## Feature-level acceptance & validation
- Детерминированное (pytest): контракт MCP (add/search/list/delete, скоупы, персистентность между рестартами), паттерн-фильтр секретов.
- Smoke-эвал ≥5 сценариев: диалоги-фикстуры → факт извлечён в правильный scope; recall влияет на ответ; удаление исключает из recall; секрет не записан; противоречие консолидировано. Прогон при изменении правил автозаписи/модели.
