# specs/wiki — Вики проекта (skill aec-wiki)

## Overview & requirement link
Ref: SPECIFICATION.md — G2; UR6 (агент обновляет вики только по команде); AC3; C7 (язык вики — настройка проекта).
Базис: бандловый скилл Hermes `research-llm-wiki` (операции ingest/query/lint/update; слои raw → wiki → SCHEMA), адаптированный под AEC-домен.

## Behavior (BDD / Gherkin)
Scenario: Первичное построение вики
  Given проект с проиндексированными источниками
  When пользователь командует «построй вики проекта»
  Then агент создаёт страницы в <vault>/wiki/ согласно SCHEMA.md
  And каждая страница имеет YAML-frontmatter (title, type, tags, sources, updated)
  And каждый содержательный факт снабжён провенансом [src: ...] на источник
  And index.md (каталог) и log.md (журнал) обновлены

Scenario: Инкрементальное обновление
  Given вики построена, детект пометил изменённые файлы источников
  When пользователь подтверждает «обновить вики по изменениям»
  Then агент повторно обрабатывает только изменённые источники
  And обновляет затронутые страницы, фиксируя изменения в log.md
  And при конфликте нового и старого значения оформляет блок «противоречие» (обе версии, документы, даты) — молчаливой перезаписи нет

Scenario: Ручная правка сохраняется
  Given инженер вручную отредактировал страницу вики
  When агент позднее обновляет эту страницу
  Then правки человека не затираются: обновление аддитивное/точечное с учётом текущего содержимого
  And при невозможности совместить — конфликт выносится в блок «противоречие» и упоминается в отчёте агента

Scenario: Язык вики
  Given settings.wiki_lang = "auto" и русскоязычные источники
  When агент создаёт страницы
  Then страницы пишутся по-русски; при wiki_lang = "en" — по-английски (термины оригинала в скобках при необходимости)

Scenario: Lint
  When пользователь командует «проверь вики»
  Then агент выдаёт отчёт по серьёзности: битые wikilinks, страницы-сироты, устаревшие страницы (sha источника изменился после updated), незакрытые противоречия, нарушения frontmatter

Scenario: Query по вики
  Given вики содержит страницы по теме
  When пользователь задаёт обзорный вопрос («что известно про электроснабжение объекта?»)
  Then агент отвечает по страницам вики со ссылками на страницы (и транзитивно — на источники)

## Data schemas (структура и SCHEMA)
```
<vault>/wiki/
  SCHEMA.md      # правила домена: таксономия, типы страниц, правила линковки
                 # (генерируется из дефолта, редактируется владельцем)
  index.md       # каталог страниц, по строке на страницу
  log.md         # журнал действий агента (append-only)
  raw/           # снапшоты обработанных источников: markdown после Docling;
                 # frontmatter: source_id/rel_path, sha256, ingested_at. Не редактируются.
  entities/      # объект, здания/сооружения, системы (ОВ/ВК/ЭОМ/…), смежники, ТУ-документы
  concepts/      # требования и ограничения (нормативные, площадки, заказчика), принятые решения
  comparisons/   # сводки противоречий и редакций
  queries/       # сохранённые содержательные ответы
```
Дефолтная AEC-таксономия тегов: `object, building, system/<марка>, discipline, tu, task, constraint, decision, contradiction, site`.
Правила страниц: создание — при упоминании в ≥2 источниках или центральности в одном; ≥2 исходящих wikilink; страница >200 строк — сплит на подтемы; каждый факт — с [src: ...].
Снапшоты raw/ — текстовые (markdown), их sha256 связан с index.db → детект дрейфа источника и офлайн-провенанс.

## API contracts
Отдельный MCP не требуется. Скилл использует: `aec-rag` (rag_query), `aec-sources` (чтение), штатные файловые инструменты Hermes в пределах vault. Интенты: build / update / lint / query.

## Edge cases
- Страница удалена человеком → lint помечает осиротевшие ссылки; агент не восстанавливает без команды.
- Источник отключён (detached) → страницы остаются с пометкой «источник отключён» (см. specs/workspace-sources).
- Очень большой источник (сотни страниц ТУ) → несколько страниц по разделам, не одна простыня.
- Смешанные языки при wiki_lang=auto → язык большинства источников.

## Feature-level acceptance & validation
- AC3 SPECIFICATION — сквозной ручной сценарий на эталонном проекте.
- Детерминированное (pytest/юниты): генератор структуры wiki/ и дефолтной SCHEMA; парсер frontmatter; lint-проверки (фикстуры: битая ссылка, сирота, дрейф sha, незакрытое противоречие).
- Smoke-эвал (≥5 сценариев): построение на мини-фикстуре 5–8 документов → рубрика: покрытие ключевых фактов, валидность провенанса (каждый [src:] существует и подтверждает факт), отсутствие выдумок; обновление с конфликтом → противоречие оформлено явно. Прогон обязателен при изменении промпта скилла или модели.
