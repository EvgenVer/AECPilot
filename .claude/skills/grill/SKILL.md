# Clarify the idea

Start from what the user already supplied and confirmed project context. Do not ask
for the idea again, walk every checklist item, or reopen settled choices.

- Ask a small number of concrete questions only about consequential gaps. Explain the
  decision in plain language and offer useful options when the host supports them.
  Follow the host's question format; allow free-text answers. If a question was not
  visible, restate it plainly instead of assuming an answer.
- Use [coverage prompts](assets/interview-checklist.md) only when helpful. Skip dimensions
  already answered or irrelevant. Distinguish suggestions from actual user decisions.
- For substantive planning, write/update DESCRIPTION using the canonical Purpose,
  Audience, Context template. Put detailed requirement/acceptance answers in the
  relevant SPECIFICATION sections rather than duplicating the idea.
- For a brainstorm without document intent, provide a concise summary; force no file.
- Missing material answers remain explicit questions. Do not invent consent or
  decisions, but continue independent clarification/preparation that does not depend
  on them.

This skill does not write PLAN/TASKS or authorize implementation. Return clarified
inputs to the shared workflow; use planning when needed, without an automatic extra
interview or stop after an already resolved question.
