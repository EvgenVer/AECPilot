## Смена курса 2026-08-05 — что изменилось и почему

Вышел Hermes 0.20.0 («The Herald Release», тег `v2026.8.3`, ~3650 коммитов). Разбор релиза
и интервью с владельцем дали пять решений, переписывающих курс:

| # | Решение | Что отменяет |
|---|---|---|
| **D1** | **Канал поставки ядра — git по SHA.** Автор прекратил публикацию в PyPI и Homebrew; поддерживаются только shell-установщик, Docker и Nix. Их установщик клонирует репозиторий и ставит editable — мы делаем то же самое, но в свой изолированный venv и по неизменяемому SHA. | Прежнее правило «ставим только из PyPI ради неизменяемости и подписи происхождения» — у него больше нет носителя |
| **D2** | **Берём их UI-стек целиком**: Tailwind v4, shadcn/Radix, nanostores, React Query, Codicon, их форма i18n. | Решение 10 фазы 1.6 («вариант C: Tailwind в наш рендерер не добавляется ни на одном батче») |
| **D3** | **Где функционал совпадает — ставим их компонент, наш выбрасываем.** Цель — получать их оптимизацию (60 fps, виртуализация, 14× стриминг markdown) и их тесты, а не воспроизводить поведение. | Правило «батчи 2–7: их код читаем как спецификацию, разметку пишем свою» |
| **D4** | **Правило объёма перевёрнуто: берём всё, кроме закрытого списка** (SPEC §Non-Goals «Исключения из Hermes»). | Прежние non-goals N7, N11, N12, N13, N15 и половина N14 |
| **D5** | **Внешний вид — их, как есть.** Наш дизайн-слой (`design/tokens.css`, макеты Claude Design) перестаёт быть обязательным артефактом и удаляется из репозитория. | «`design/` — источник истины для оболочки» |

Что **не** изменилось и является рамкой всего остального: приложение остаётся нашим
(SPEC C8) — мы не форкаем их десктоп и не живём плагином внутри их приложения. Основание:
только так сохраняется право не включать то, чего нет в списке исключений. Проверено, что
альтернативы этого не дают: плагин не может убрать ни одной их поверхности, а форк с
перестройкой UI делает вливание их же обновлений дороже, а не дешевле.

## Architecture

Слои (сверху вниз):

1. **AECPilot Desktop** (Electron + React + TypeScript) — единственный UI.
   - **Рендерер — на стеке донора** (D2): Tailwind v4 с их темой, примитивы shadcn/Radix,
     состояние в nanostores, серверное состояние в React Query, иконки Codicon, i18n в их
     форме с каталогами `en`/`ru`.
   - **Оболочка — их система размещения**: виджет-грид, плавающие панели, несколько окон,
     вкладки сессий (UR12). Наши активности встраиваются в неё как вклады.
   - **Наши собственные поверхности** (их у донора нет): проводник vault + источники,
     вьюеры PDF/DOCX/XLSX/CSV, вики, docgen, статус индексации.
2. **hermes-agent** (Python, пин по SHA) — агентное ядро **без модификаций**; приложение
   запускает его локальным процессом (`hermes serve`) и общается по tui_gateway JSON-RPC/WS
   **плюс REST того же процесса** (тот же хост, порт и токен). Персона и язык агента —
   SOUL.md профиля; проектные правила — AGENTS.md в vault.
3. **AEC-расширения** (наш переносимый слой):
   - MCP `aec-sources` — read-only доступ к источникам (контракт: `specs/workspace-sources.md`).
   - MCP `aec-rag` — Docling-парсинг + LightRAG-индекс per-project + запросы с цитатами
     (контракт: `specs/qa-over-sources.md`); сюда же файловый индексер (sha256, детект изменений).
   - Память — без собственного MCP: слой 1 — записка ядра (`MEMORY.md`/`USER.md`),
     слой 2 — их провайдер Mem0 локально (Phase 5).
   - Skills: `aec-qa` (эталон), `aec-wiki`, `aec-docgen`; `aec-id-check` — post-MVP.
4. **Хранилище** — files-first: vault + `.aecpilot/` (SQLite+FTS5 `index.db`, LanceDB,
   конфиг, логи). Серверов нет (C4).

Границы модулей (monorepo):
```
apps/desktop/            # Electron + React (TypeScript)
  src/main/              # main-процесс: мост к шлюзу, файловые операции, safeStorage
  src/renderer/src/
    donor/               # ИХ код с указанием происхождения (см. §Слой донора)
    aec/                 # наши поверхности: проводник, источники, вьюеры, вики, docgen
    shared/              # адаптеры: мост шлюза, i18n, наши атомы
mcp/aec_sources/         # Python, MCP-сервер (stdio)
mcp/aec_rag/             # Python: индексер + Docling + LightRAG + MCP-сервер
skills/                  # skill-паки
runtime/                 # установка и запуск ядра, слепки контрактов, пробы
eval/                    # эвал-датасеты и раннер
specs/                   # поведенческие контракты
```

Ключевые решения:
- Working dir агента = vault; источники агенту доступны **только** через `aec-sources`
  (N3/AC6 обеспечиваются конструкцией инструментального слоя).
- Детект изменений — наш индексер (sha256 по интервалу), без LLM; действия — по подтверждению.
- **Рендерер не открывает WebSocket к шлюзу сам** (SPEC C9). Их клиент шлюза (`@/hermes`)
  адаптируется к нашему IPC-мосту — это единственный шов, который мы правим обязательно.
- Embedding-модель фиксируется в конфиге проекта; смена = полный re-ingest.

## Слой донора — как именно берётся их код

Это операционное ядро нового курса. Правила обязательны: от их соблюдения зависит, будет
ли следующее обновление Hermes стоить часы или недели.

**Точка съёмки.** Коммит донора фиксируется константой `DONOR_SHA` в `runtime/donor-env.mjs`
вместе с версией их десктопа. Читаем и переносим только с этого коммита; клон
`D:\my program\Hermes\hermes-agent` держим на нём же (read-only, вне воркспейса).

**Вендорная зона.** Их файлы живут в `renderer/src/donor/**`, повторяя их структуру путей.
Каждый файл начинается заголовком: исходный путь, `DONOR_SHA`, лицензия MIT, перечень
внесённых правок. Файл `LICENSE` донора сохраняется в поставке.

**Разрешены ровно четыре вида правок их файлов.** Всё остальное не правим — иначе повторный
перенос при их обновлении превращается в слияние:
1. импорт их клиента шлюза → наш IPC-мост (`shared/gateway-bridge`);
2. импорт их i18n → наш каталог (ключи их, строки наши);
3. удаление вкладов, попадающих в SPEC §Non-Goals (регистрация поверхности, не её логика);
4. снятие импортов, которых у нас нет (их облако, их бренд, их телеметрия).

**Слой состояния.** Их атомы (nanostores) переносятся вместе с экраном, который их читает.
Атомы, обращающиеся к шлюзу, перенаправляются на мост; атомы, хранящие настройки — на наш
`storage`. Свой параллельный стор для тех же данных не заводим: две модели состояния хуже
любой одной.

**Тесты.** Их тесты переносятся вместе с файлом, если не тянут их сторы. Наши тесты на
чистые функции (`*-pure.ts`) сохраняются как есть — они пиннят измеренные контракты ядра и
от стека не зависят.

**Обновление.** При переходе на новую версию донора файл переносится заново с нового SHA, а
не патчится. Дифф наших четырёх правок восстанавливается по заголовку файла.

**Наши поверхности** (`renderer/src/aec/**`) пишутся в том же стеке, но их кодом не
являются: проводник, источники, вьюеры, вики, docgen, индексация. У донора аналогов нет.

## Stack & package managers

- Desktop: TypeScript, React, Electron; сборка electron-builder; пакетный менеджер pnpm.
- Python-слой: Python 3.12, менеджер uv (venv + lockfile); MCP — официальный python SDK.
- Тесты: pytest (python), Vitest (UI-юниты и компонентные), Playwright (e2e smoke).
- Линтеры: ruff (py), eslint + prettier (ts).

| Инструмент | Пин | Основание |
|---|---|---|
| hermes-agent | **0.20.0, пин по коммиту** (`HERMES_SHA` в `runtime/hermes-env.mjs`; тег `v2026.8.3`, релиз 2026-08-03; MIT; requires-python `>=3.11,<3.14`) | их репозиторий; PyPI-канал закрыт автором |
| Python | 3.12.13 (проходит их `requires-python`; 3.14 несовместим) | endoflife.date |
| uv | 0.11.x, ≥0.11.26 | PyPI |
| Node.js | 24 LTS для нашей сборки; ядру Node 26 **не нужен** (замер 1.7.3, ниже) | endoflife.date + их `package.json` |
| Electron | 43.x, ≥43.0.0 | endoflife.date |
| pnpm | 11.x, ≥11.10.0 | npm registry |

**Почему пин по SHA, а не по тегу.** Релиз в PyPI был неизменяем и подписан происхождением;
git-тег автор может передвинуть. SHA фиксирует содержимое криптографически — это не слабее
хэша колеса. При установке проверяем, что тег релиза указывает на этот SHA.

**Нужен ли ядру Node 26** (ответ задачи 1.7.3: **нет**). Строка «Hermes requires Node >=26»
из релиз-нот живёт в `scripts/install.sh` как текст предупреждения; реальные пороги там же
и в их манифесте другие: `engines.node = ">=22.22.0"`, функция `node_satisfies_build()`
пропускает всё от 22.22, а сам установщик кладёт себе `NODE_VERSION="22"`. Node ядру нужен
только для двух поверхностей, которых у нас нет (`hermes_cli/dep_ensure.py`: «required for
browser tools and TUI») и для сборки их веб-дашборда — мы запускаем `hermes serve` с
`--skip-build`. Проверено на живом ядре: `serve.mjs smoke` на Node 22.22.3 (наша машина)
проходит, шлюз отдаёт `gateway.ready`. **Пин Node не поднимаем.**

Отдельная ловушка на будущее: их `engines.npm = "<11.10.0 || >=11.17.0"` при
`engine-strict=true` исключает штатный npm Node 24 (11.16.0). Нас это не касается, пока мы
не запускаем `npm ci` внутри их дерева (мы пользуемся pnpm в своём приложении), но если
такой шаг когда-нибудь появится — он упрётся именно сюда, а не в версию Node.

**Почему установка editable, а не из git-URL** (измерено задачей 1.7.2). Их `setup.py`
отказывается собирать wheel или sdist в принципе — любой `pip install <git-url>` падает с
`RuntimeError: Building wheels or sdists for hermes-agent is not supported`, и единственный
предложенный путь — `uv pip install -e .`. Поэтому `runtime/setup.mjs` делает shallow-fetch
ровно нужного коммита в `runtime/.hermes-src` (detached, gitignored, не рабочая копия) и
ставит оттуда editable. Следствия: каталог исходников — часть установки и не удаляется;
`site-packages` не содержит их модулей, поэтому всё, что читает ядро с диска (снимальщик
контракта), адресует `HERMES_SRC_DIR`, а не `site-packages`.

**Два Python-окружения и как они сведены** (задача 1.7.9). Ядро живёт в
`runtime/.hermes-venv` со своими точными пинами; наши MCP-серверы — в корневом
uv-workspace. Замер 2026-08-05: в обоих `mcp==1.28.1` и `starlette==1.3.1`, расходится
только `anyio` (4.14.2 против 4.14.1) — патч, следствие независимого разрешения.

Сводить их в одно окружение мы не будем и точные пины ядра к себе не переносим: наши
серверы говорят с ядром по **протоколу через stdio**, а не по ABI, — версии клиента и
сервера MCP расходиться имеют право, в этом смысл протокола. Единственное, чего диапазон
`mcp>=1,<2` делать не должен, — опускаться ниже версии, запиненной ради безопасности.
Поэтому floor зафиксирован тестом (`mcp/aec_sources/tests/test_dependency_floor.py`):
`starlette >= 1.0.1` (исправление CVE-2026-48710) и мажор `mcp` = 1. Тест ходит в
установленное окружение, поэтому ловит и откат зависимости, и разъезд мажора.

**Пара assistant-ui пиннится ТОЧНЫМИ версиями и апгрейдится только вместе:**
`@assistant-ui/react-streamdown` держит `@assistant-ui/react` жёстким peer-ом узкого
диапазона, а семейство релизится ежедневно. Перед апгрейдом:
`npm view @assistant-ui/react-streamdown@<v> peerDependencies`.

## Data / API / integrations

- **tui_gateway (JSON-RPC/WS)** — основной контракт. В 0.19.1 шлюз разрезан: `server.py` +
  `methods_{complete,config,prompt,session,tools}.py`. Ссылки вида `server.py:NNNN` в наших
  документах и комментариях после этого указывают в никуда — адресуем по **модулю и имени
  метода**, а не по строке.
- **REST того же процесса** — `hermes serve` = алиас `dashboard`, поднимает FastAPI на том же
  хосте/порту/токене (`X-Hermes-Session-Token`). Часть маршрутов вынесена в
  `hermes_cli/web_routers/{cron,git,mcp,profiles,sessions,skills,tools}.py`, остальное — в
  монолите `web_server.py`. Правило: что есть в RPC — идёт по RPC; REST только там, где RPC
  не покрывает (профили, MCP CRUD, история сохранённых сессий, граф обучения).
- **Ключи провайдеров — только в нашем safeStorage** и в spawn-env процесса ядра. Их
  `model.save_key` и `POST /api/env/reveal` не используются никогда: оба работают с открытым
  текстом. В 0.20.0 появился `${env:VAR}` SecretRef в `config.yaml` и MCP — это разрешённый
  способ сослаться на переменную окружения вместо значения.
- **Approvals (UR11)** — три значения `approvals.mode` в `config.yaml` профиля; ядро
  перечитывает конфиг на каждой команде, смена применяется живо.
- **MCP-контракты наших серверов** — в `specs/` (`sources_*`, `rag_*`).

**Конвейер слежения за ядром** (обязательная часть каждого обновления):
1. `runtime/contract-snapshot.mjs` — снимает слепок установленного ядра: набор `@method`
   (теперь по пяти `methods_*.py`), эмитируемые события, REST-маршруты (`web_routers/` +
   монолит), дефолты `hermes_cli/config.py`, `Requires-Dist`.
2. `runtime/contract-diff.mjs` — **новый**: сравнивает два слепка и выдаёт «сломалось /
   появилось / **молча сменило умолчание**». Третья категория — главная: урок 0.18→0.19
   (`model.options` перестал форсировать `include_unconfigured`, ответ ужался с 41 провайдера
   до 3 без единой ошибки).
3. `runtime/parity-registry.mjs` — **новый**: генерирует реестр паритета (AC9) из ядра и
   из дерева донора, сверяет со списком исключений SPEC и с нашими вкладами.

## Validation strategy

- Детерминированное: `uv run pytest` (MCP-серверы, индексер, RO-негативные), `pnpm test`
  (vitest: `*.test.tsx` → jsdom + @testing-library, `*.test.ts` → node), `pnpm e2e`
  (Playwright smoke).
- Перенесённые тесты донора идут в общий прогон и считаются нашими.
- Эвалы (`ai-eval-design`): `eval/qa_dataset.yaml` (≥30, baseline → порог O1/AC2); smoke-эвалы
  `aec-docgen` и памяти; обязательный прогон при изменении skill-промптов, модели,
  embedding-модели, RAG-параметров — иначе оформленный waiver.
- Безопасность: `security-review` в конце Phase 2 и Phase 6; отдельно — проверка UR19
  (внешние каналы выключены по умолчанию, AC10) и R11 (каталог плагинов ядра).
- Контракт ядра: `contract-diff` без непрочитанных расхождений + `serve.mjs smoke`,
  `aec-sources-check`, `checkpoint-probe`, `skills-probe`, `hermes-event-diff`.

## Risks & tradeoffs

- **Канал поставки ядра (R1).** Установка из исходников по SHA вместо подписанного колеса.
  Цена: сборка требует git и сети, подпись происхождения PyPI утрачена. Компенсация: SHA
  неизменяем, сверяется с тегом релиза; при необходимости офлайн-воспроизводимости фаза 5
  собирает колесо один раз и фиксирует его хэш.
- **Стек донора без гарантий (R12).** Их SDK «always-current», версионирования нет; Tailwind
  и shadcn дрейфуют. Принято ради того, чтобы их код переносился копированием. Контроль —
  вендорная зона с указанием происхождения, четыре разрешённых правки, повторный перенос
  вместо патчей.
- **Замена ~16 000 строк нашего рендерера.** Переписывается разметка и CSS
  (10 626 `.tsx` + 5 360 `.css`); выживают 7 124 строки чистой логики, 6 231 строка тестов
  на неё, 13 389 строк main/preload/project/shared и весь Python. Работа идёт под сеткой:
  наши компонентные тесты писались с утверждениями по отрисованному дереву, а не по классам.
- **Внешние каналы (R10).** Проектные данные получают путь наружу, а агент — путь внутрь.
  Принято решением владельца; удерживается тем, что каналы выключены по умолчанию, включение
  явное и показывает уходящие данные (AC10).
- **Каталог плагинов ядра (R11).** Существует независимо от нашего решения его не
  использовать; агент умеет писать файлы. Свой загрузчик не заводим (HX5), каталог держим
  вне рабочей папки агента.
- **Удалённый режим (R13).** Ломает все файловые поверхности; каждая обязана либо работать
  удалённо, либо явно отключаться с объяснением.
- **Двойной рантайм (Node + Python)** → сложнее упаковка (R5); принято ради ядра и
  python-экосистемы RAG.
- **Embedded-хранилища** → пределы масштаба (R3); принято ради «без серверов» (C4).
- **Облачные эмбеддинги в MVP** → быстрый старт; цена — полный re-ingest при переходе в
  закрытый контур (C5).
- **3 skills в MVP** → риск распыления снижен выводом `aec-id-check` (N9); эталонный только
  `aec-qa`.

Каждая фаза заканчивается: тесты зелёные → self-review → коммит → сверка планов.
