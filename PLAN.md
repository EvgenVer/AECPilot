## Technical decisions

- Architecture: Electron + React + TypeScript — единственный UI, рендерер на стеке донора (Tailwind v4, shadcn/Radix, nanostores, React Query, Codicon); ядро hermes-agent без форка и модификаций запускается локальным процессом `hermes serve`; наш переносимый слой — MCP `aec-sources` (read-only источники) и `aec-rag` (Docling + LightRAG, ответы с цитатами), скилы `aec-qa` и `aec-wiki`, память ядра + Mem0; хранилище files-first — vault + `.aecpilot/` (SQLite+FTS5, NanoVectorDB LightRAG), серверов нет. Подробно — `docs/plan-details.md` §«Architecture» и §«Слой донора — как именно берётся их код».
- Course: пять решений смены курса 2026-08-05 (D1 ядро из git по SHA, D2 их UI-стек целиком, D3 их компонент вместо нашего, D4 «берём всё, кроме закрытого списка», D5 их внешний вид); приложение остаётся нашим (SPEC C8). Подробно — `docs/plan-details.md` §«Смена курса 2026-08-05 — что изменилось и почему».
- Stack: TypeScript, React, Electron, electron-builder, pnpm через corepack; Python 3.12 + uv; тесты pytest, Vitest, Playwright; линтеры ruff, eslint + prettier. Пины версий — `docs/plan-details.md` §«Stack & package managers»; пин ядра — `runtime/hermes-env.mjs`.
- Dependencies: каждая проходит `dependency-vetting` перед установкой, версии фиксируются lock-файлами, лицензии по SPEC C3. Перечень и обоснования — `docs/plan-details.md` §«Selected dependencies».
- Vendored code: код Hermes Desktop лежит в `apps/desktop/src/renderer/src/donor/**` по `DONOR_SHA` с шестью разрешёнными правками — правила в `AGENTS.md` §Project rules.

### Integrations

- Ядро hermes-agent (MIT): пин по коммиту в `runtime/hermes-env.mjs`, установка `node runtime/setup.mjs` в изолированный `runtime/.hermes-venv`; процесс `hermes serve` слушает только 127.0.0.1 (SPEC C11); контракт — tui_gateway JSON-RPC/WS плюс REST того же процесса с токеном сессии; рендерер говорит со шлюзом только через main (SPEC C9). Конвейер слежения за ядром — `docs/plan-details.md` §«Data / API / integrations».
- Наши MCP-серверы `aec-sources` и `aec-rag` (`mcp/`): контракты — `specs/workspace-sources.md`, `specs/qa-over-sources.md`; регистрация в профиле ядра — `runtime/register-aec-*.mjs`.
- Провайдеры LLM и эмбеддингов: OpenAI-совместимые endpoint'ы (SPEC C5); ключи только в нашем safeStorage и в окружении процесса ядра, `model.save_key` и `POST /api/env/reveal` не вызываются; OAuth-вход провайдеров ведёт ядро (SPEC C10).
- Память Mem0: их провайдер, локально в профиле ядра; обязанности слоёв — `specs/agent-memory.md`.

## Verification

- Детерминированное: `uv run pytest` (MCP-серверы, индексер, RO-негативные), `pnpm test`
  (vitest: `*.test.tsx` → jsdom + @testing-library, `*.test.ts` → node), `pnpm e2e`
  (Playwright smoke + `acceptance` на mock-шлюзе); прогон приёмки `pnpm e2e:acceptance`
  (живое ядро, с ходами модели по `AEC_ACCEPTANCE_LIVE=1`) — по требованию и после каждого
  подъёма пина, см. §«Автоприёмка чек-листа».
- Перенесённые тесты донора идут в общий прогон и считаются нашими.
- Эвалы (`ai-eval-design`): `eval/qa_dataset.yaml` (≥30, baseline → порог O1/AC2); smoke-эвалы
  памяти; обязательный прогон при изменении skill-промптов, модели,
  embedding-модели, RAG-параметров — иначе оформленный waiver.
- **Чужой скил перед принятием меряется плечами на эталонном наборе** — правила каждого
  плеча лежат отдельным файлом в `eval/variants/`, чтобы разница была ровно одна и была
  видна. Первый такой замер — `grounded-citations` (задача 3.22). Он и дал правило, по
  которому теперь берутся чужие скилы: **брать вместе с его механикой, а не пересказывать
  правилами.** Перенесённое ТРЕБОВАНИЕ без его же ПРОВЕРКИ дало 59 % дословных выдержек из
  обещанных 100 %; их скрипт в цепочке — 7 из 7. Плечо без механики — не «облегчённый
  вариант», а видимость гарантии, и меряется оно затем, чтобы это было числом, а не мнением.
- Безопасность: `security-review` в конце Phase 2 и Phase 6; отдельно — проверка UR19
  (внешние каналы выключены по умолчанию, AC10) и R11 (каталог плагинов ядра).
- **Компонентный тест донора берётся только после замера стоимости импорта.** Замер
  на задаче 3.9: тест, который лишь импортирует `@/app/messaging`, идёт **52,7 с** —
  vitest трансформирует всё дерево экрана на каждый прогон. В сборке этого нет (vite
  бандлит один раз), но их собственные тесты рендерят экран внутри кейса, и первый же
  не укладывается ни в один разумный таймаут. Вместо теста, который не влезает,
  пишется проверка по исходникам (регистрация, контракт) плюс проба против живого
  ядра. Бывшая находка D-31.
- Контракт ядра: `contract-diff` без непрочитанных расхождений + `serve.mjs smoke`,
  `aec-sources-check`, `checkpoint-probe`, `skills-probe`, реестр паритета
  (`parity-registry`). **`hermes-event-diff` снят 2026-08-24 (находка D-35).** Он
  спрашивал «на какие события ядра ИХ интерфейс реагирует, а НАШ нет» и читал для
  этого наш список обработчиков — `renderer/src/chat/chat-state.ts`, удалённый в
  1.8.9 вместе с нашим чатом. Своего списка событий у нас больше нет: их держит код
  донора, и вопрос закрывает реестр паритета (AC9), у которого единица не событие,
  а экран. Тот же корень, что и у секции `ourEvents` в `contract-snapshot`, снятой
  при 3.B0.
- **Проверка.** `corepack pnpm lint` (eslint, typecheck, prettier, ruff, audit; `uv` не на PATH — ruff/pytest звать из `.venv\Scripts`), `corepack pnpm test` (vitest + pytest; vitest гонять из Git Bash, см. §Environment quirks), `corepack pnpm e2e` (smoke + acceptance на моке), `node runtime/checklist-coverage.mjs` (обязан сказать «Сошлось»). Живой прогон `corepack pnpm e2e:acceptance` стоит денег модели — по требованию и после подъёма пина; см. `docs/acceptance/README.md`.
- **Чек-лист и тесты связаны номером.** Позиция `<блок>.<шаг>.<✓>` в `docs/manual-checklist.md` с меткой `[e2e]`/`[live]` обязана иметь тест, чьё имя начинается с этого номера; `test.fail` считается, `test.fixme` — нет. Новые блоки приёмки идут в чек-лист под следующим свободным номером (сейчас 57), а не под номером страницы приёмки — на этом счётчик уже краснел.
- Документы планирования: `python .agents/skills/planning/scripts/check_docs.py check --root .` после декомпозиции или закрытия фазы и других структурных правок.
- Реестры паритета (`corepack pnpm parity`) читают номера и статусы задач из таблиц `TASKS.md`; ссылка вердикта на несуществующую или закрытую задачу — ошибка «ССЫЛКА В НИКУДА».
