# Вики проекта

Проектная документация приходит десятками файлов от разных смежников, в разных
редакциях и без общей картины. Вики — это картина: страница на предмет, факты
со ссылками на документы, связи между страницами.

**Ты не пересказываешь документы, ты собираешь из них связное знание.** Разница
в том, что пересказ можно прочитать один раз, а вики — это то, куда возвращаются
через полгода и находят, откуда взялось число.

## Что ты не делаешь

- **Не пишешь ничего, чего нет в документах.** Общие знания об электроснабжении
  и вентиляции — не источник: в этом проекте может быть иначе.
- **Не трогаешь `wiki/raw/`** руками — это снимки разобранных документов, их
  пишет инструмент.
- **Не переписываешь `SCHEMA.md`** без прямой просьбы: это правила владельца.
- **Не строишь и не обновляешь вики по своей инициативе.** Только по команде
  (SPEC UR6). Индексация, вопрос по документам, любая другая работа — не повод.

## Инструменты

| Что нужно | Инструмент |
|---|---|
| Создать скелет вики перед первой сборкой | `mcp_aec_rag_wiki_init` |
| Записать снимки разобранных документов в `raw/` | `mcp_aec_rag_wiki_snapshot` |
| Что вообще есть в проекте: сущности, связи, охват | `mcp_aec_rag_rag_overview` |
| Найти конкретное значение или строку | `mcp_aec_rag_rag_query` |
| Проверить дословную выдержку перед тем, как её записать | `mcp_aec_rag_rag_check_quote` |
| Сколько документов проиндексировано, есть ли устаревшие | `mcp_aec_rag_rag_status` |
| Читать и писать страницы | штатные файловые инструменты, в пределах vault |

## Операция build — первичное построение

Команда звучит как «построй вики проекта».

### 1. Осмотрись, прежде чем писать

- `rag_status` — сколько документов в индексе. `files_indexed = 0` значит
  строить не из чего: скажи это и предложи проиндексировать.
- `rag_overview` — что за проект, какие сущности и связи уже видны.
  Посмотри `graph_scope.covers_whole_project`: если `false`, вика будет
  построена по части проекта, и **это надо сказать вслух до начала**, назвав
  число документов вне графа.

### 2. Скелет и снимки — инструментами

```
wiki_init()        # папки, SCHEMA.md, index.md, log.md
wiki_snapshot()    # wiki/raw/*.md — снимки разобранных документов
```

Оба безобидны при повторном вызове. Снимки **не переписывай руками**: у них в
заголовке `sha256`, по которому потом видно, что источник ушёл вперёд.

### 3. Реши, какие страницы заводить

Прочитай `wiki/SCHEMA.md` — правила владельца сильнее того, что написано здесь.
По умолчанию страница заводится, если предмет:

- упомянут **в двух и более источниках**, либо
- занимает центральное место в одном (объект, здание, система по марке).

Раскладка по папкам: `entities/` — объект, здания, системы, смежники, документы
ТУ; `concepts/` — требования, ограничения, принятые решения; `comparisons/` —
противоречия и редакции; `queries/` — сохранённые ответы.

Не заводи страницу на каждое упоминание. Двадцать полезных страниц лучше двухсот
страниц-заглушек: заглушки не находят, а вики с ними выглядит наполненной.

### 4. Напиши страницу

Каждая страница начинается с YAML-заголовка — ровно этих полей:

```markdown
---
title: ТП-1
type: entity
tags: [object, system/ЭОМ]
sources: ["tasks/ЭОМ/задание_ред2.pdf", "tasks/Ведомости/кабели.xlsx"]
updated: 2026-08-17
---
```

`type` — одно из `entity`, `concept`, `comparison`, `query`. `sources` — файлы,
из которых взяты факты страницы, в виде `<источник>/<путь>`. `updated` — дата,
когда ты её тронул.

Дальше текст. Три правила, каждое обязательно:

**Факт — со ссылкой.** Формат ровно такой:

```
[src: <source_id>/<rel_path>#<locator>](#cite)
```

Локатор из поля `locator` результата: `{"page": 12}` → `p12`,
`{"sheet": "Ведомость", "range": "C5:D6"}` → `Ведомость!C5:D6`,
`{"heading": "Кабельный журнал"}` → `h:Кабельный журнал`, `{}` → части после `#`
нет вовсе. Не уверен в локаторе — не пиши его: ссылка на файл честнее
придуманного якоря.

Факт без ссылки — это мнение, и в вики ему не место. Если хочется написать
связку («следовательно», «то есть»), она не нуждается в ссылке, потому что она и
не факт; но и утверждением о проекте она быть не должна.

**Не меньше двух ссылок `[[…]]` на другие страницы.** Страница без связей
выпадает из вики: её не найдут ни поиском по связям, ни глазами из каталога.
Ссылка на ещё не написанную страницу — нормально, её напишут следующей.

**Дословная выдержка — через проверку.** Если приводишь фразу источника,
сначала пропусти её через `rag_check_quote`; `ok: false` значит, что этой фразы
там нет, и в страницу она не идёт. Копируй из текста фрагмента, не набирай по
памяти.

Страница длиннее 200 строк разбивается на подтемы отдельными страницами.

### 5. Противоречия — обоими вариантами

Два разных значения одного и того же (типично: две редакции задания) не
разрешаются молча. На странице темы — блок:

```markdown
## Противоречие: установленная мощность

| Значение | Документ | Дата |
|---|---|---|
| 250 кВт | [src: tasks/ЭОМ/задание_ред2.pdf#p12](#cite) | 2026-03-14 |
| 180 кВт | [src: tasks/ЭОМ/задание.pdf#p11](#cite) | 2025-11-02 |

Действующая редакция не определена — решение за инженером.
```

И сводка в `comparisons/`. Выбрать редакцию — решение инженера, а не твоё; дата
берётся из текста документа, а не из файловой системы, и если её там нет — так и
пиши «дата не указана».

### 6. Каталог и журнал

`index.md` — по строке на страницу: ссылка `[[…]]`, тип, одна фраза о чём она.

`log.md` дописывается снизу, старое не трогается:

```markdown
## 2026-08-17 — построение

Построено 14 страниц по 23 документам. Вне графа знаний: 0.
Противоречий оформлено: 2 (мощность ТП-1, отметка пола 1 этажа).
```

### 7. Скажи, что сделал

В ответе — сколько страниц, по скольким документам, сколько противоречий, что
осталось непокрытым. Не пересказывай содержание вики: её только что написали,
её прочитают.

## Операция update — обновление по изменениям

Команда звучит как «обнови вику по изменениям». **Только по команде**: сам,
после индексации или по ходу другой работы, вику не обновляй (SPEC UR6).

### 1. Спроси, что уехало

```
wiki_stale()
```

Три списка, и с каждым поступают по-своему:

| Список | Что это | Что делать |
|---|---|---|
| `changed` | документ переиздали — страницы по нему описывают прошлую редакцию | перечитать документ, обновить его страницы |
| `new` | документ проиндексирован, но в вики его нет | решить, заводить ли страницу — по тем же правилам, что при построении |
| `gone` | снимок есть, а документа в индексе больше нет | **ничего не удалять**; пометить страницы «источник отключён» |

Все три пусты — так и скажи: «вики совпадает с индексом, обновлять нечего».
Ходить в поиск после этого не надо.

### 2. Работай только с изменившимся

Перечитывай **только затронутые документы**, а не весь проект: обновление на
двух изменившихся файлах не должно стоить как построение с нуля.

```
wiki_snapshot(rel_paths: ["ЭОМ/задание_ред3.pdf"])
```

### 3. Новое значение не затирает старое молча

Если у изменившегося документа значение стало другим, чем записано на странице,
это **противоречие редакций**, а не исправление опечатки. Оформи блоком — обе
версии, оба документа, даты, — и добавь сводку в `comparisons/`.

Молчаливая перезапись — самая дорогая ошибка, которую здесь можно сделать:
инженер, читавший вику вчера, не узнает, что цифра изменилась, а вика не
покажет, что когда-то было иначе.

Исключение одно: страница явно описывала прошлую редакцию как прошлую (в блоке
противоречия), и новая редакция это подтверждает — тогда просто дополни блок.

### 4. Отметься в журнале

```markdown
## 2026-08-17 — обновление

Изменилось документов: 2. Обновлено страниц: 3.
Новых противоречий: 1 (мощность ТП-1: 250 → 320 кВт).
Источник tasks/Смежники отключён, страницы по нему помечены.
```

`updated` в заголовке каждой тронутой страницы — на сегодня. Нетронутые страницы
не трогай вовсе: `updated`, поменявшийся без изменения содержимого, врёт diff'у.

## Чужая правка страницы — не перезаписывается никогда

Вику правит не только ты. Инженер дописывает то, чего в документах нет: устную
договорённость со смежником, вывод из совещания, пометку «уточнить у
заказчика». Стереть это — худшее, что здесь можно сделать: он не узнает, что
текст пропал, а восстановить будет неоткуда.

**Перед тем как тронуть хоть одну страницу:**

```
wiki_edited()
```

| Список | Что это |
|---|---|
| `edited` | человек изменил страницу после того, как ты её написал |
| `unknown` | страницу завёл человек, либо отпечатков нет вовсе |

Обе означают одно: **эту страницу нельзя переписать целиком**. Прочитай её,
пойми, что там сейчас, и правь точечно — добавь факт в нужный раздел, обнови
значение в своей строке, допиши блок противоречия. Абзацы, которых ты не писал,
остаются как есть, включая те, что кажутся тебе неточными: это чужая работа, а
не твой черновик.

Не получается совместить — новое утверждение прямо спорит с тем, что дописал
человек, — **не выбирай**. Оформи блоком «Противоречие» обе версии: его как
есть, своё со ссылкой на документ, — и назови это в отчёте отдельной строкой,
чтобы человек увидел.

**В конце сборки или обновления, когда все страницы записаны:**

```
wiki_checkpoint()
```

Этим ты говоришь «вот в таком виде я вику оставил». Забудешь — следующий запуск
сочтёт все страницы чужими и будет осторожничать там, где мог бы работать
свободно. Это неприятно, но безопасно; наоборот было бы наоборот.

## Операция lint — проверка вики

Команда звучит как «проверь вику».

```
wiki_lint()
```

Проверка механическая, её делает код: «убедись, что все ссылки ведут куда-то»
ты выполнял бы добросовестно ровно до той страницы, на которой устанешь, и
никогда не сказал бы, где именно устал.

Находки приходят от худших к меньшим:

| Серьёзность | Что бывает | Что это значит |
|---|---|---|
| `error` | битая ссылка, нарушение заголовка | навигация сломана сегодня |
| `warning` | сирота, устаревшая страница | вика есть, но ей нельзя доверять целиком |
| `info` | незакрытое противоречие | не дефект вики — вопрос к инженеру |

### Как отчитаться

Сгруппируй по виду, а не вываливай список: «четыре битые ссылки на трёх
страницах», а не четыре строки подряд. Для каждой группы скажи, чем чинить.

Устаревшие страницы — повод предложить обновление (`update`), а не чинить их
поштучно.

Незакрытые противоречия **не чини вовсе**: выбор редакции это решение инженера.
Назови их и всё.

### Чего не делать

**Не правь молча.** Особенно битые ссылки: `[[Щитовая]]` без страницы означает
одно из двух — страницу ещё не написали (тогда её надо написать) или её удалил
человек (тогда удалять надо ссылку, и спросить). Догадаться, что именно, из
отчёта нельзя.

Прежде чем править хоть что-то, посмотри `wiki_edited()`: страница из `edited`
или `unknown` — чужая работа, и молча её трогать нельзя.

## Операция query — ответ по вики

Команда звучит как обзорный вопрос: «что известно про электроснабжение
объекта?».

Отвечай **по страницам вики**, а не поиском по документам: в этом и смысл вики
— она уже свела разрозненное вместе. Читай страницы файловыми инструментами,
начиная с `wiki/index.md`.

- Ссылайся на **страницы**: `[[ТП-1]]`. Читатель дойдёт по ним до источников —
  провенанс на страницах уже стоит.
- Если факт важен, приведи и ссылку на документ, которую страница несёт: две
  ступени провенанса лучше одной.
- Вики пуста или темы в ней нет — **так и скажи** и предложи два выхода:
  построить вику (`build`) либо ответить обычным поиском по документам
  (это скилл `aec-qa`, вопрос переадресуется ему).
- Устарела — предупреди: `wiki_lint()` покажет страницы, чей источник
  переиздан. Ответ по устаревшей странице без предупреждения хуже отказа.

Хочешь сохранить ответ — положи его в `queries/` отдельной страницей с обычным
заголовком и ссылками. Но только если попросили: `queries/` не свалка всего, о
чём когда-либо спрашивали.
