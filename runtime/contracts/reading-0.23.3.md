# Разбор контракта ядра 0.23.0 → 0.23.3 (задача T85)

Слепок `hermes-0.23.3.json` снят 2026-11-21 с реестра установленного дерева `caafe538`
(`node runtime/contract-snapshot.mjs`, формат 4): методов 263 в 105 модулях (было 261 в 100),
маршрутов 335 (было 316), событий 47, дефолтов конфига 970 (было 962), маркеров чекпойнтов 9.
Сравнение — `node runtime/contract-diff.mjs`: сломалось 4 (после правки слепка), появилось 33,
молча сменило 54. Тела наших методов сверены по отдельному клону без содержимого файлов
(`git show v0.23.0:` / `v0.23.3:`), закреплённое `runtime/.hermes-src` не трогалось. Решение —
[0023](../../docs/decisions/0023-core-0-23-3.md).

## 0. Ложные находки инструментов

- **«Наша поверхность: 29 методов вместо 40».** Ядро ни одного не убрало — все 11 на месте в
  `gatewayMethods`. Это наш переход на единый шлюз (T53): `main/index.ts` больше не зовёт
  `agents.list`, `process.list`, `session.activate/branch/compress/delete/history/steer/title/undo/usage`
  сам — окно ходит к ним через проход RPC. Прежний слепок снят 2026-11-08, до T53.
- **«Сломались 9 маркеров чекпойнтов».** Модуль переехал: `tools/checkpoint_manager.py` →
  `agent/checkpoints/manager.py` (`prune_checkpoints` — в `agent/checkpoints/maintenance.py`),
  переходника на старое имя ядро не оставило. Слепок читает оба пути; пробы `checkpoint` и
  `kanban` переведены на новые модули (ловушка 5 подъёма: пробы держатся за приватные имена).

## 3. Тихо сменившиеся умолчания — решения

| Ключ | Было → стало | Решение |
|---|---|---|
| `tools.tool_search.defer` | + `text_to_speech`, `manage_connections` | наш список пишется целиком (`agent-defaults-pure.ts`): оба имени добавлены, прежний список 0.22–0.23.0 — в `PREVIOUS_DEFERRED_TOOLS`, чтобы профили обновились; иначе модель видела бы их в каждом запросе |
| `agent.clarify_timeout` | 3600 → 90 с | берём, как у ядра: вопрос агента без ответа отпускает ход через 90 с («пользователь не ответил»); написанное вместо ответа снимает вопрос сразу. Требования в PRODUCT нет — сказано владельцу в отчёте |
| `prompt_caching.cache_ttl` | `5m` → `auto` | берём: срок кэша промптов выбирает ядро по провайдеру |
| новые `delegation.auto_resume*` | `auto_resume: false` | выключено у ядра — субагенты после перезапуска шлюза сами не продолжаются |
| новый `security.redact_phone_numbers` | `true` | в пользу: номера телефонов маскируются в журналах |
| новый `approvals.approvers` | `["*"]` | кто может подтверждать команды; у нас один человек |
| `voice.auto_tts_mode`, `telegram.extra.plain_drafts`, `agent.codex_request_compression`, `gateway.sessiondb_loop_guard`, `prompt_caching.route_ttl_ceilings` | новые | не наш путь или безопасные умолчания ядра |

Зависимость `av==18.1.0` (extra `voice`) — закрепление PyAV ради faster-whisper: с PyAV 19
каждая расшифровка падала с `TypeError` (#135245). Нужна диктовке T59.

## 5. Главные исправления, ради которых подъём (решение 0023)

- **Ответ MCP-инструмента — один раз.** Проверено бесплатно на `aec-sources`: `sources_read` и
  `sources_tree` отдают текст и `{"result": …}`; на 0.23.0 модель получала обе копии, на 0.23.3
  путь модели (`_render_call_tool_result(…, for_model=native_images)`, `native_images` — у
  обработчика, которого зовёт цикл агента) оставляет одну.
- **Слушатель шлюза под Windows** переживает оборванное в очереди подключение (`9a837ab2`,
  `cd300c7b`).
- Правила подтверждения команд PowerShell, проверка доверия MCP при отсутствующей записи,
  oauthlib 4.0.1, opentelemetry 1.45.2.
