**Разбор диффа 0.19.0 → 0.20.0 (результат задачи 1.7.6).**

*Ограничение отчёта, важное для доверия к нему:* раздел «молча сменило умолчание» для
этого перехода **слеп** — слепок 0.19.0 сделан форматом 1 и умолчаний не записывал.
Сравниватель честно об этом говорит («умолчания параметров не сравниваются») и не выдаёт
141 метод ядра за «появилось». Категория становится рабочей начиная со следующего
обновления. Компенсация здесь — эмпирическая: пробы 1.7.7 и проверка того, что ни один
наш метод и ни один наш маршрут не исчез.

По нашим поверхностям:
- **Исчезло: ничего.** Все 45 методов и 8 маршрутов, которые вызывает main-процесс,
  присутствуют в 0.20.0 (снимальщик не выдал ни одного «метод не найден»).
- **32 расхождения** — из них 30 это разрез шлюза 0.19.1 (`server.py` → `methods_*.py`)
  плюс переписанные тела. Крупнейшие: `prompt.submit` 1096 → 269 строк (вынесен в
  хелперы), `command.dispatch` 552 → 641, `session.resume` 376 → 419, `rollback.diff`
  125 → 23, `reload.mcp` 99 → 150, `config.set` 839 → 754. Ни одно из них не изменило
  контракт вызова там, где есть проба; остальное закрывается ручной приёмкой 1.8.22.
- **`model.options` перепроверен точечно** — ровно тот метод, ради которого заведена
  третья категория. `methods_complete.py`: `include_unconfigured=bool(params.get(...))`,
  то есть по-прежнему FALSE по умолчанию, и мы по-прежнему передаём флаг явно
  (`apps/desktop/src/main/index.ts`, `ipcMain.handle('model:options')`). Экран провайдеров
  не схлопнется.
- **События**: `runtime/hermes-event-diff.mjs` (перенаправлен на `ui-tui/src`, см. 1.7.7)
  нашёл пять событий, которые мы не обрабатываем и не игнорируем → D-15.
- **Одна измеренная регрессия** на нашей поверхности → D-14.

Ответы на четыре обязательных вопроса:
1. **Серверный источник артефактов не появился.** В 0.20.0 нет ни одного RPC с `artifact`
   в имени и ни одного REST-маршрута `/api/artifact*` (проверено по слепку: 141 метод,
   233 маршрута). Слово `artifact` встречается только в англоязычных комментариях не по
   теме (`tui_gateway/methods_prompt.py:611`, `server.py`). Артефакты остаются понятием
   клиента — задача 1.8.13 переносит их компонент, а не подключается к серверу.
2. **`session.list` скоуп по рабочей папке НЕ получил.** `tui_gateway/methods_session.py`,
   `@method("session.list")`: единственные параметры — `limit` (умолчание 200) и выбор
   профиля через `_profile_db(params)`; фильтрация — deny-list по `source` (`kanban`,
   `tool`), не по каталогу. Привязка сессий к проекту остаётся нашей. Отдельно появилось
   семейство `projects.*` (11 RPC, включая `projects.for_cwd` и `projects.list`) — это
   другая модель, и решение, брать ли её вместо нашей привязки, принимается в 1.8.11.
3. **Число `kind` у индикатора сжатия не изменилось — по-прежнему два.**
   `tui_gateway/server.py::_status_update` перетегирует `lifecycle` в `kind="compacting"`,
   когда в тексте есть `COMPACTION_STATUS_MARKER` (`agent/conversation_compression.py`,
   «Compacting context»); ручное сжатие шлёт `kind="compressing"` из
   `methods_session.py`, `@method("session.compress")`. Пер-ходовая микро-компакция
   **выключена по умолчанию** (`hermes_cli/config_defaults.py`: `micro_compact: False`,
   `micro_compact_every_n_turns: 1`) и пишет **телеметрию в лог**
   (`ContextCompressor._emit_micro_compaction_telemetry`), а не `status.update` — то есть
   индикатор не замигает каждый ход даже если её включить.
4. **Контракт подруливания не изменился.** `methods_session.py`,
   `@method("session.steer")`: параметр `text` обязателен (иначе 4002), ответ
   `{status:"queued"|"rejected", text}`, ошибка 4010 «agent does not support steer» — ровно
   то, что записано в `specs/agent-sessions.md` §Подруливание. Композерная половина тоже
   на месте: `server.py::_handle_busy_submit` по-прежнему применяет
   `display.busy_input_mode` и отвечает `queued`/`steered`/`streaming`.
