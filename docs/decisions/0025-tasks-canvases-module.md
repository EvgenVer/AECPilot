# 0025 — Задачи, Гант и холсты: служба в главном процессе, отдельные окна, dotpm копией, Excalidraw 0.18.1

- Date: 2026-11-26
- Status: accepted
- Approved by: owner
- Changes: дополнение объёма 0.2 — [PRODUCT](../PRODUCT.md) UR58–UR63, AC17, AC18

## Context

Пример. Инженер перетаскивает карточку «Расчёт узла У-5» в колонку «В работе» в окне доски.
В ту же минуту агент по его просьбе сдвигает срок этой карточки. Окно Ганта и холст со
схемой узла открыты на втором мониторе. Обе правки должны сохраниться и сразу появиться во
всех окнах. Правку агента должно быть видно в истории, и её можно отменить.

Решить нужно пять вещей:
- где работает код, который читает и пишет файлы задач и холстов (служба);
- как к ней приходит агент;
- как устроены окна;
- в каком виде берём готовый код dotpm и Excalidraw;
- как файлы лежат в папке проекта.

## Options

### Где работает служба

#### Главный процесс Electron — выбрано

- Advantages:
  - Пишет один процесс, поэтому правки не теряются и не нужна сверка двух писателей.
  - Главный процесс уже держит проект, файлы и наблюдатель за хранилищем, а окна получают
    изменения через уже существующий IPC.
  - Логика dotpm написана на TypeScript и работает здесь без переписывания.
  - Журнал правок агента для отмены ведётся в одном месте.
- Limitations:
  - Инструменты агента доступны, пока открыта программа. Это не новое ограничение: шлюз ядра и
    так живёт с окном ([0017](0017-single-gateway.md)).
  - В режиме «сервер + ноутбук» служба оказалась бы на ноутбуке, а ядро — на сервере, поэтому
    в 0.2 этот режим выключен (UR63). Для сервера службу придётся вынести отдельным процессом
    рядом с ядром.
  - Тяжёлый расчёт (раскладка плана) нельзя делать прямо в потоке главного процесса: если он
    займёт заметно больше 0,1 с, его выносим в рабочий поток (`worker_threads`), иначе окна
    замрут.
- Cost and effort: наименьшие из трёх.
- Changing it later: средне. Служба пишется отдельным модулем с узким интерфейсом, поэтому
  вынести её в свой процесс для режима сервера — это перенос модуля, а не переписывание.

#### Отдельный MCP-сервер на Python рядом с `aec-rag`

- Advantages: в режиме сервера сразу стоит рядом с документами.
- Limitations:
  - Два писателя одних файлов (сервер и окна через главный процесс), нужна сверка.
  - Логику dotpm пришлось бы переписать на Python и держать две копии правил.
- Cost and effort: высокие.
- Changing it later: дорого.

#### Свой процесс на Node, который запускает ядро

- Advantages: один писатель и один язык, режим сервера ближе.
- Limitations: ещё один процесс, канал связи с главным процессом и риск процесса-сироты.
- Cost and effort: примерно вдвое больше первого варианта.
- Changing it later: средне.

### Как агент приходит к службе

MCP-сервер внутри главного процесса, по HTTP на 127.0.0.1:
- **Порт** свободный, выбирается на старте.
- **Токен** новый на каждом запуске программы. Ядро передаёт его заголовком `Authorization`.
  В `config.yaml` хранится только ссылка на переменную окружения `${AEC_TASKS_TOKEN}`; сам
  токен приходит шлюзу в окружении при запуске.

Ядро умеет удалённые MCP-серверы с `url` и `headers` и подставляет в них переменные окружения
профиля (`tools/mcp_tool_config.py`). Без токена служба отвечает 401. Другого входа, кроме
127.0.0.1, нет (C11).

### Окна

Каждый вид — своё окно `BrowserWindow`:
- **Сборка.** Окно открывает тот же рендерер с адресом вида (`?win=board`, `?win=gantt`,
  `?win=canvas&id=…`), как сейчас всплывающее окно браузера (`windows-pure.ts`).
- **Мост.** Мост preload тот же; окно видит только свой проект.
- **Положение.** Положение и размер окна запоминаются по проекту и виду, отдельно для
  каждого холста.
- **Синхронизация.** Изменения рассылает главный процесс событием `tasks:changed` или
  `canvas:changed` всем окнам проекта. Правка извне (агент, другой процесс, файл изменён
  руками) приходит тем же событием через наблюдатель хранилища (T74).

### Код dotpm

#### Копия в репозитории — выбрано

- Advantages:
  - Нужные файлы `@dotpm/core` (модель задачи, YAML, расчёт сроков по зависимостям) и
    отрисовка Ганта из `@dotpm/ui` лежат у нас, их можно править свободно.
  - Привязку к Obsidian всё равно меняем на свою.
  - Если автор забросит проект, у нас ничего не сломается.
- Limitations: исправления автора переносим руками, когда они нужны.
- Cost and effort: малые.
- Changing it later: легко.

#### Пакеты npm по точной версии

- Advantages: обновление одной командой.
- Limitations: внутри ничего не изменить; пакеты молодые (0.2.0), и их интерфейс будет
  меняться.

#### Своё по их образцу

- Advantages: полный контроль.
- Limitations: медленнее и с новыми ошибками, которые у них уже исправлены.

### Excalidraw

#### Стабильная 0.18.1 — выбрано

Есть всё нужное:
- картинки, рамки, Mermaid, русский;
- `customData` и `link` у элементов;
- свой React внутри элемента `embeddable` (`renderEmbeddable`) — это живая карточка задачи;
- выгрузка в картинку, слияние сцен.

Стикер — наша кнопка: цветной квадрат с текстом. Шрифт он сам не подстраивает. Мини-карты
нет. Переход на 0.19 — одна задача после её выпуска, формат файла совместим.

#### Предварительная сборка `next`

- Advantages: настоящие стикеры и мини-карта сразу.
- Limitations: интерфейс библиотеки меняется до выпуска.

## Decision

- Служба задач и холстов работает в главном процессе (`apps/desktop/src/main/workbench/`):
  она одна пишет файлы, рассылает изменения окнам, ведёт журнал правок агента и открывает
  агенту MCP по HTTP на 127.0.0.1 с токеном запуска.
- Доска, Гант и каждый холст — отдельные окна того же рендерера. Видимое собрано на
  компонентах приложения (shadcn/Radix, Tailwind, наши переменные темы).
- Код dotpm (MIT) копируется в `apps/desktop/src/shared/vendor/dotpm/` с заголовком
  происхождения в каждом файле. В отличие от зоны донора, правки свободные, но перечислены в
  заголовке (правило в `AGENTS.md` §Project rules).
- Excalidraw — npm `@excalidraw/excalidraw` 0.18.1 точной версией.

**Раскладка по исполнителям.** Своя функция последовательной расстановки по ресурсам
(serial schedule generation scheme): задачи по порядку зависимостей и приоритета ставятся на
самого раннего свободного человека подходящей роли.
- Работает в рабочем потоке главного процесса.
- Результат — черновик, который показывает Гант. Агент вызывает расчёт инструментом и сам
  ничего не считает.
- Запасной путь — OR-Tools (Apache-2.0, около 24 МБ). Он нужен, только если простая
  расстановка на реальных планах окажется заметно хуже.
- Плагин каталога SolverForge Workbench (Apache-2.0) рассмотрен 2026-11-27 и пока не взят
  (решение владельца). Подходит только его модель Task scheduling: навыки, отпуска, сроки,
  перепланирование и объяснение плана.

  Мешало:
  - его страницы в окне требуют загрузчик плагинов окна (HX5);
  - Windows у автора не проверяется;
  - данные лежат в профиле агента, а не в папке проекта;
  - агенту он даёт 37 инструментов.

  Путь возврата — только движок этой модели (около 25 МБ, JSON на входе и выходе) за нашей
  кнопкой «Разложить», после проверки на Windows.

**Хранение в папке проекта:**

```
<проект>/
  tasks/
    people.yaml            список исполнителей проекта (имя, роли, цвет)
    board.yaml             колонки доски: статусы, цвета, порядок, скрытые
    <id>-<название>.md     одна задача: YAML-шапка (поля dotpm + наши) и описание в Markdown,
                           ниже — раздел комментариев
  canvases/
    <название>.excalidraw  один холст (JSON Excalidraw, без картинок внутри)
    <название>.files/      картинки этого холста по их id (PNG/JPEG/WebP)
  .aecpilot/
    workbench-journal.jsonl  журнал правок: кто (человек/агент), запрос агента, до/после
```

Папки `tasks/` и `canvases/` в индекс документов не попадают: агент читает их своими
инструментами, а ответы по документам ссылаются только на документы. Комментарии к объекту
холста лежат в файле холста (`customData` объекта), комментарии к задаче — в её файле.

## Consequences

- **Новые зависимости.**
  - `@excalidraw/excalidraw` 0.18.1 (MIT, около 19 МБ в сборке окна).
  - `@modelcontextprotocol/sdk` (MIT) — MCP-сервер в главном процессе.
  - Копия dotpm (MIT). Все три попадают в `THIRD-PARTY-NOTICES.txt`.
- **Новый слушающий порт** на 127.0.0.1 — с токеном и отказом без него. Его проверяет обзор
  безопасности этапа и вносит в `THREAT_MODEL.md`.
- **Профиль ядра.** Регистрация сервера `aec-workbench` в `config.yaml` пишется тем же путём,
  что и наши MCP, с именем профиля явно (N16).
- **Задача агенту** (исполнитель «агент») создаёт новый сеанс проекта через шлюз и отправляет в
  него текст задачи с вложениями. Итог агент пишет инструментом `task_comment` и ставит статус
  «На проверку».
- **Агенту нужно видеть холст картинкой**, когда окно холста закрыто. Служба отрисовывает его
  в скрытом окне через выгрузку Excalidraw. Если отрисовать не удалось, агент получает текст
  объектов и предупреждение.
- **Режим сервера** — отдельной задачей следующей версии: служба выносится процессом рядом с
  ядром, окна приходят к ней через туннель.
