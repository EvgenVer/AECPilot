# 0004 — Хранилище files-first: vault, SQLite FTS5, NanoVectorDB LightRAG

- Date: 2026-07-06 (files-first, без серверов); 2026-08-15 (векторное хранилище)
- Status: accepted
- Approved by: owner

## Context

Проектная организация не должна поднимать сервер ради продукта; бэкап проекта должен быть
копией папки (C4, Guardrails). Индексу нужны полнотекстовый поиск и векторы, графу — хранилище
LightRAG. Пользователи держат проекты по путям с кириллицей (`D:\проекты\ЖК …`).

## Options

### Файлы + SQLite FTS5 + встроенный NanoVectorDB LightRAG — chosen

- Advantages: ни одного сервера; всё внутри `<vault>/.aecpilot/`; FTS5 находит точные
  формулировки и марки, векторы — смысл.
- Limitations: KV-хранилище LightRAG — JSON-файлы, читаемые целиком (замер 2.18: 1622
  фрагмента — 110 МБ диска, 303 МБ памяти, открытие 11,3 с); потолок около 5000 фрагментов
  (≈1 ГБ памяти); `nano-vectordb` не обновлялся с ноября 2024.
- Cost and effort: смена хранилища = полный повторный ingest.
- Changing it later: costly.

### LanceDB (из первоначального плана)

- Limitations: в LightRAG 1.5.6 такого бэкенда не существует.

### Faiss

- Limitations: не работает с путями в Unicode (faiss#3073 закрыт без исправления) — сломался
  бы на кириллическом vault; тоже держит индекс в памяти.

### Milvus Lite, Qdrant, PostgreSQL

- Limitations: Milvus Lite официально не поддерживает Windows; остальные требуют сервер
  (против C4).

## Decision

Файлы — источник истины. Индекс проекта — `<vault>/.aecpilot/index.db` (SQLite: таблицы
файлов, фрагментов, полнотекстовый `files_fts` на FTS5, состав графа, распознанные
страницы, ошибки), векторы и граф — встроенные хранилища LightRAG в
`<vault>/.aecpilot/lightrag/` (NanoVectorDB, JSON KV, NetworkX). Модель эмбеддингов
фиксируется в настройках проекта; её смена — полная переиндексация.

## Consequences

- Порядок действий при росте: сначала убрать `full_docs` (не читается ни в одном
  сценарии), затем заменить KV на SQLite, и только третьим — векторный слой (запасной путь —
  свой поиск на sqlite-vec, не Faiss).
- Три правила LightRAG противоречат модели проекта и обойдены в `lightrag_bridge`
  (дедупликация по имени файла и по хэшу, глобальное состояние на процесс) — проверять при
  каждом обновлении LightRAG (R18).
- Каждая новая библиотека, получающая путь vault, проверяется на кириллице поимённо (R16).
- Схема — [данные](../data.md).
