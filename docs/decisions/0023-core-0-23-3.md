# 0023 — Подъём ядра на v0.23.3 до диктовки

- Date: 2026-11-21 (разбор выпусков и ответ владельца)
- Status: accepted (сменит пин v0.23.0 из решения [0016](0016-core-0-23-0.md), когда задачи
  T85–T88 будут закрыты)
- Approved by: owner

## Context

Пока собиралась версия 0.2, у Hermes вышли три патча: v0.23.1 (2026-11-09), v0.23.2
(2026-11-16) и v0.23.3 (2026-11-19, `caafe538`), всего около 12 тысяч коммитов. Подробные
заметки авторы обещают только с v0.24.0, поэтому разбор шёл по дереву: отдельный клон без
содержимого файлов, `donor-report` против нашей зоны, сверка наших методов шлюза и приватных
импортов ядра.

Что задевает нас напрямую:

1. **Текст документа доходит до модели дважды.** Сервер на `MCPServer` отдаёт ответ
   инструмента `-> str` или `-> list` и текстом, и как `{"result": …}`; ядро 0.23.0 вторую
   копию не убирает. Проверено на `aec-sources` (`sources_read`) на временном файле: обе копии
   на месте. Это двойная цена чтения документов и выгрузка в файл при половине размера.
   Исправлено в v0.23.2 (`36d40638`).
2. **Шлюз под Windows перестаёт принимать подключения**, если клиент оборвал соединение в
   очереди: процесс жив, окно получает «connection refused». Исправлено в v0.23.3
   (`9a837ab2`, `cd300c7b`). С нашей стороны не обходится — правка внутри ядра.
3. **PyAV 19 ломает faster-whisper 1.2.1**: каждая расшифровка падает с `TypeError`. v0.23.3
   закрепляет `av==18.1.0`; на 0.23.0 диктовка T59 начиналась бы с обхода.

Попутно: правила подтверждения команд PowerShell, проверка доверия MCP при отсутствующей
записи, обновления oauthlib, opentelemetry, tornado.

## Options

### Поднять на v0.23.3 сейчас, до T59 — chosen

- Advantages: три ошибки закрывает ядро; диктовка строится на исправленном ядре.
- Limitations: в зоне донора изменились 262 из 2119 файлов, 26 из них с нашими правками, три
  источника исчезли; хранилище ядра переведено на новый слой, сменились умолчания (сокращение
  старых результатов инструментов, срок кэша промптов `auto`, новый API для Gemini 3+).
- Cost and effort: задачи T85–T88, примерно вдвое меньше подъёма на v0.23.0.
- Changing it later: costly.

### Остаться на v0.23.0 и закрыть своё

- Advantages: дешевле: вторую копию в наших серверах и PyAV закрываем у себя.
- Limitations: ошибка слушателя шлюза под Windows остаётся; следующий подъём больше.

### Ждать v0.24.0 с подробными заметками

- Limitations: дата неизвестна; T59 всё равно требует обхода.

## Decision

1. Пин — стабильный `v0.23.3` (`caafe5389ae585ef77387a962aee05b1bcf17029`).
2. Порядок тот же, что у [0016](0016-core-0-23-0.md): установка и сверка контракта, перенос
   донора, полные проверки, обзор свежим взглядом.
3. Electron нашего приложения — на 44.10.0 (у Hermes поднят из-за CVE-2026-111497).

## Consequences

- T59 (диктовка) идёт после T88.
- Прежние решения об объёме (0016, пункт 9) не меняются.
