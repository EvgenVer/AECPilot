# 0001 — Ядро hermes-agent без форка, через шлюз, пин по SHA из git

- Date: 2026-07-06 (ядро без форка), 2026-08-05 (канал поставки — git по SHA, решение D1)
- Status: accepted
- Approved by: owner

## Context

Продукту нужен агент: разговор с моделью, инструменты, MCP, субагенты, память, навыки,
выбор провайдера. Писать это самим — годы работы; брать чужое ядро — значит жить в его
темпе (релиз раз в 2–3 недели по ~3600 коммитов, R1). С 0.20.0 автор прекратил публикацию
в PyPI и Homebrew — прежний канал установки исчез (SPEC C1, A6).

## Options

### hermes-agent как отдельный процесс, через публичный шлюз, пин по SHA — chosen

- Advantages: готовый агент и экосистема (skills, MCP, профили, Mem0); их собственный
  десктоп работает на том же шлюзе (A4); обновление — подъём пина, а не слияние.
- Limitations: ядро нельзя поправить у себя — дефект ядра ждёт апстрим (так ждёт подпись
  A2A, T49); темп изменений требует слепка контракта и его диффа на каждом подъёме;
  установка из исходников требует git и сети при сборке.
- Cost and effort: подъём пина — отдельная фаза работ (фаза 2 — 15 задач).
- Changing it later: costly — на контракт шлюза завязаны главный процесс и вся зона донора.

### Форк ядра

- Advantages: можно чинить дефекты у себя.
- Limitations: каждое их обновление — слияние с нашими правками; теряется смысл брать
  чужое ядро.
- Cost and effort: постоянная работа по слиянию.
- Changing it later: hard.

### Свой агентный слой поверх SDK модели

- Advantages: полный контроль.
- Limitations: заново писать инструменты, память, MCP-клиент, навыки, каналы.
- Cost and effort: многократно больше всего MVP.
- Changing it later: hard.

## Decision

Ядро — hermes-agent (MIT) без форка и без модификаций (C1). Интеграция — только публичные
поверхности: tui_gateway JSON-RPC/WS и REST того же процесса `hermes serve`. Версия
пиннится коммитом стабильного тега `vX.Y.Z`, а не тегом и не номером: тег автор может
передвинуть, SHA неизменяем; при установке проверяется, что тег указывает на этот SHA.
Установка — `node runtime/setup.mjs`: shallow-fetch коммита в `runtime/.hermes-src` и
editable-установка в изолированный venv (их `setup.py` отказывается собирать колесо).
AEC-специфика живёт в нашем переносимом слое — свои навыки и MCP-серверы (C2).

## Consequences

- Пин — константа `HERMES_SHA` в `runtime/hermes-env.mjs`; карта тегов и ловушки подъёмов —
  [core-facts.md](../core-facts.md).
- Каждый подъём: слепок контракта (`runtime/contract-snapshot.mjs`), дифф с прошлым
  (`contract-diff.mjs`), пробы `runtime/*-probe.mjs`, перенос донора, полный e2e и приёмка.
  Опаснее всего тихая смена умолчания — отсюда обязательный дифф.
- Автообновления ядра нет; проверку обновлений ядро не делает (`updates.check: false`).
