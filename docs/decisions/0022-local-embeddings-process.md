# 0022 — Локальная модель эмбеддингов: процесс ведёт приложение, модель — в своей папке

- Date: 2026-11-18
- Status: accepted
- Approved by: owner
- Changes: задача T83 (UR53, решение [0021](0021-index-providers-split.md))

## Context

Пример: инженер выбирает в «Индекс и память» → эмбеддинги «Локальная модель» и нажимает
«Скачать». Векторы фрагментов должна строить модель bge-m3 (выбрана замером T83,
`eval/reports/embedding-bench.md`) на этом компьютере. Для этого нужен работающий
сервер llama.cpp в режиме эмбеддингов (`llama-server --embeddings`) — новый процесс в
архитектуре.

Ядро умеет ставить свою закреплённую сборку llama.cpp (UR39) и качать модели с Hugging Face,
но его рантайм — маршрутизатор чат-моделей: дочерние процессы запускаются без
`--embeddings`, а модель в его папке `models/` попадает в список моделей чата. Поэтому
нужно решить, кто ведёт процесс и где лежит модель.

## Options

Процесс:

1. **Приложение (выбрано).** Главный процесс поднимает сервер, когда выбрана локальная модель,
   и гасит его при выходе; остаток после сбоя гасит при следующем старте по записанному номеру
   процесса — только если номер всё ещё принадлежит `llama-server`. Минус: пока окно открыто,
   модель держит около 0,7 ГБ памяти видеокарты.
2. **Сервер индекса сам.** Движок поднимается при первом вычислении векторов и гаснет после
   простоя. Минус: у индекса три разных процесса (поиск в чате, индексация, граф) — нужен общий
   замок; сложнее, выше риск оставшихся процессов.
3. **Без встроенного процесса.** Человек ставит Ollama или LM Studio сам и вписывает адрес
   (работает с T80). Не выполняет «Скачать» из UR53.

Модель:

1. **Своя папка (выбрано)** `<профиль ядра>/aec/embedding-models`. В списке моделей чата не
   появляется. Загрузку с Hugging Face (докачка, проверка SHA256) пишем сами; поиск по Hugging
   Face берём у ядра; «из файла» — запоминаем путь, без копии.
2. **Общая папка моделей ядра.** Загрузку, поиск и «из файла» даёт код ядра целиком, но
   bge-m3 появляется в списке моделей чата как модель, с которой нельзя разговаривать.

## Decision

Процесс ведёт приложение, модель — в своей папке (ответы владельца 2026-11-18). Движок —
сборка ядра: её ставит задание ядра `POST /api/local-models/runtime/install` (CUDA на NVIDIA,
Vulkan на AMD/Intel, иначе CPU — их `binaries.select_backend`), находит ядро своим
`binaries.installed_engine`; одна копия на машину вместе с локальными чат-моделями.
Код: `apps/desktop/src/main/local-embeddings.ts`, правила — `local-embeddings-pure.ts`.

## Consequences

- Сервер слушает только 127.0.0.1, порт по умолчанию 47821, занятый — заменяется свободным и
  запоминается в `aec/local-embeddings.json`, чтобы адрес в окружении индекса не менялся.
- Локальная модель только строит векторы: модель разбора (граф) и память при выборе
  «как у индекса» берут провайдера разбора.
- При подключении к ядру на другой машине пункт выключен со словами (UR20): модель ставится
  там, где работает ядро.
- Окно модели 8192 токена; нарезчик индекса держит фрагмент таблицы до 8 000 знаков
  (сжатие выравнивания docx, T83).
