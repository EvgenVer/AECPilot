# 0019 — Библиотеки документов — отдельным окружением в поставке

- Date: 2026-11-12 (опрос владельца), реализация 2026-11-13 (T66)
- Status: accepted
- Approved by: owner
- Replaces: решение интервью 2026-11-08 «дополнения `documents` в venv ядра»

## Context

Инженер просит агента: «сделай ведомость в Excel» или «оформи записку в Word». Это делает
навык ядра `microsoft-office` (и навыки docx/xlsx/pptx/pdf): он пишет файлы библиотеками
`python-docx`, `openpyxl`, `python-pptx`, `reportlab`, `pypdf`, `pdfplumber`, `pypdfium2`.
У Hermes эти библиотеки — дополнения ядра `documents` и `documents-pdf`; навык ищет
интерпретатор так: сначала `python` машины, затем команда ядра
`hermes pm environment documents --extra documents --extra documents-pdf`, которая при
первом вызове **скачивает** библиотеки и строит отдельное окружение.

В поставке 0.1 навык не работал (замер 2026-11-12): `python` терминала агента этих
библиотек не знает, а команду `hermes pm …` наш шлюз `runtime/bin/hermes_gate.py`
отклоняет — он пропускает только `hermes -p <специалист> chat` (D-165: агент однажды
поставил MCP-сервер через CLI ядра мимо карточки согласия). Скачивание из сети без
согласия к тому же противоречит правилу продукта.

## Options

### В venv ядра

- Advantages: +≈29 МБ (часть зависимостей — `lxml`, `PIL`, `cryptography` — там уже есть).
- Limitations: агенту пришлось бы дать интерпретатор, из которого импортируется само ядро, —
  `python -m hermes_cli` в обход `approvals.deny` (D-165). К тому же venv ядра в поставке
  не запускается своим `python.exe`: в его `pyvenv.cfg` путь машины сборки.

### Отдельное окружение только для документов — chosen

- Advantages: агент получает «голый» интерпретатор поставки, в пути которого есть только
  библиотеки документов, ядра нет. Работает без сети. Версии — те же, что в `uv.lock` ядра.
- Limitations: +≈61 МБ на диске (общие с ядром `PIL`, `lxml`, `cryptography` — второй копией).
- Cost and effort: одна задача (T66).
- Changing it later: easy.

### Оставить как у Hermes — скачивание при первом вызове

- Limitations: нужна сеть и прохождение `hermes pm` через шлюз; противоречит D-165 и правилу
  «ничего из сети без согласия».

## Decision

Поставка несёт `runtime/core/docs-env/`: `site/` — библиотеки дополнений `documents` и
`documents-pdf` (их собственные пины из `pyproject.toml` ядра, всё остальное — по версиям
`uv.lock` ядра), и `python` — короткий shell-запускатель: интерпретатор поставки с
`PYTHONPATH=site`. Собирает её `runtime/payload/docs_env.py` при подготовке поставки
(`stage_core.py`; в разработке — тем же шагом `node runtime/setup.mjs`). Наш шлюз `hermes`
отвечает на ровно ту команду навыка путём к этому запускателю; всё остальное из
`hermes pm` по-прежнему отклоняется.

## Consequences

- Навык ядра не правится: его собственный блок «Prerequisites» находит интерпретатор через
  `hermes pm environment …` без сети. Тест `runtime/hermes-bin.test.mjs` берёт этот блок из
  `SKILL.md` ядра и падает, если при подъёме пина он изменится.
- Размер поставки: +60,9 МиБ на диске (17 пакетов, байткод не запекается — Python допишет его
  при первом импорте). Версии записаны в `runtime/payload/payload-versions.json`
  (`core.documents`); лицензии — разделом «Библиотеки документов» в THIRD-PARTY-NOTICES
  (все разрешительные: MIT, BSD, Apache-2.0, PSF).
- Запускатель — shell-скрипт: терминал агента на Windows — bash ядра. Из PowerShell
  (вариант навыка `$env:PY = hermes pm environment …`) его не запустить.
- В разработке с `setup.mjs --no-payload` окружения нет; шлюз отвечает понятным отказом.
