# 0008 — Режимы «сервер / клиент» и SSH-туннель

- Date: 2026-08-17 (интервью: SSH-туннель, сервер на Windows, один пользователь); 2026-10-16
  (сервер — `AECPilot.exe --server` без окна); 2026-10-19 (постоянный токен)
- Status: accepted
- Approved by: owner

## Context

Документы лежат на машине в офисе, инженер работает с ноутбука. Разбор документов,
индексация и вызовы модели тяжёлые; индексация по сети медленная и ненадёжная (UR25).

## Options

### Один установщик с тремя режимами; клиент приходит к шлюзу по SSH-туннелю — chosen

- Advantages: тяжёлое идёт там, где документы; MCP-серверы запускает само ядро, поэтому их
  пути всегда локальные — «индексации по сети» не возникает по построению; шлюз остаётся на
  127.0.0.1 (C11), шифрование и проверка личности — у SSH.
- Limitations: безопасность сводится к безопасности SSH-доступа (R17); многопользовательский
  режим не входит (N16); одно подключение за раз.
- Cost and effort: роли процесса, трей сервера, задача Windows на вход, смена проекта с
  клиента, ключи моделей на сервере (T31–T35.2).
- Changing it later: costly.

### Шлюз на сетевом интерфейсе

- Limitations: ядро в этом режиме пускает любой узел сети, защита — общий токен в строке
  запроса (против C11).

### Индексировать сетевую папку с ноутбука

- Limitations: медленно, ноутбук закрыт — пересканирования нет.

## Decision

Режим установки — одно слово в `<root>/install-mode.txt` (`full` / `server` / `client`).
Сервер — то же приложение с ключом `--server`: ядро на 127.0.0.1, значок в трее
(«Скопировать токен подключения», «Выдать новый токен», «Ключи моделей…», «Остановить»),
автостарт задачей Windows «AECPilot Server» при входе текущего пользователя. Токен шлюза
постоянный, хранится в safeStorage сервера, клиент вводит его один раз и хранит в своём
safeStorage. Смена проекта с клиента — `config.set {key:'cwd'}` у ядра сервера; сервер раз
в 5 с читает проект у своего ядра и открывает его у себя (регистрация MCP по местным путям,
`reload.mcp`, расписание сканирования). Ключи моделей сервера вводятся окном из трея
сервера.

## Consequences

- Обратная связь клиенту — `<проект>/.aecpilot/server-state.json`, читается файловым API ядра.
- Имя профиля передаётся явно везде, личность не выводится из токена, пользовательское не
  пишется в общемашинное — чтобы не закрыть путь к многопользовательскому серверу.
- Подробно — [plan-details.md](../plan-details.md) §«Профили поставки «сервер / клиент»»,
  сценарий — [сервер и клиент](../flows/server-client.md).
