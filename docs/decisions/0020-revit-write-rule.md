# 0020 — Запись в модель Revit: правило агента, а не вопрос программы

- Date: 2026-11-15 (интервью владельца, T69); исследование сервера — T67, T68
- Status: accepted
- Approved by: owner
- Changes: UR51 и уточнение N2 в [PRODUCT](../PRODUCT.md) (только для Revit; Lira — вместе с T61)

## Context

Инженер пишет: «поставь всем стенам 3-го этажа комментарий „проверить“» — это явная просьба
изменить модель. А агент, проверяя документацию, сам решает «исправить марку стены» — это его
инициатива. Владелец 2026-11-12: явную просьбу не переспрашивать; спрашивать (или сначала дать
план), когда агент решил что-то изменить сам.

Сервер Autodesk для Revit 2027 ([Revit MCP](../components/revit-mcp.md)) в продукт не входит:
инженер добавляет его сам в окне MCP-серверов. У каждого его инструмента есть только
аннотация `readOnlyHint`. Ядро решает, спрашивать ли человека перед вызовом, по двум вещам:
`trust` сервера и `readOnlyHint` инструмента. На `trust: untrusted` оно спрашивает перед каждым
пишущим вызовом (ответы «один раз / на этот сеанс / всегда» для пары «сервер + инструмент»);
без `trust` (так сервер записывает окно MCP) — не спрашивает никогда. Кто предложил запись,
ядро не знает. Замеры T68 на настоящем Revit это подтвердили.

## Options

1. **Правило агента.** Сервер как его пишет окно (без `trust` — ядро не спрашивает). Навык
   `aec-revit` говорит агенту: явную просьбу выполнить и показать изменения; свою идею — планом
   в чате, писать только после «да». Плюсы: ровно то, что сказал владелец; без кода в
   приложении и без правок донора. Минусы: это поведение модели, а не замок — модель может
   ошибиться и изменить модель без спроса. Потолок: пока ошибка обратима (Ctrl+Z, файл не
   сохранён), этого достаточно; если ошибки станут заметными на практике — переходить к
   варианту 3 (цена: запись `trust: untrusted` при добавлении сервера, лишний щелчок на явную
   просьбу).
2. **Спрашивает программа всегда.** `trust: untrusted`: каждая запись — окно согласия. Плюсы:
   гарантия, N2 не меняется. Минусы: на явную просьбу — лишний щелчок, против решения
   владельца; после «на этот сеанс» программа перестаёт спрашивать и за инициативу агента.
   Нужна правка: окно донора `trust` не пишет — своя запись поля при согласии.
3. **Оба слоя.** Правило агента и вопрос программы. Самое осторожное и самое назойливое.

## Decision

Вариант 1. Набор инструментов — все 40, как сервер ставится (без `--tool-permission`).
Сервер добавляется вручную в окне MCP; кнопку «найден Revit — подключить» не делаем.

## Consequences

- Навык `skills/aec-revit/SKILL.md` — правило записи, порядок работы с сервером (процесс
  Revit, `review_changes`, удаление). Попадает к агенту и в поставку вместе с остальными
  навыками из `skills/`.
- Автотест на заглушке проверяет, что сервер без `trust` пишет без вопроса программы (то есть
  правило держит агент) и что навык на месте; соблюдение правила моделью проверяет владелец
  вручную (`docs/manual-checklist.md`) или платный прогон с его согласия.
- Известные особенности окна MCP с этим сервером (вставка пути не распознаётся, кнопка
  проверки видит 1 инструмент из 40) — записаны на странице сервера, задач по ним нет.
