# Ручная приёмка — фаза 1.6, батч 1 (чат)

Один прогон `pnpm dev` на всё. Формат: **что сделать → что увидеть (✓)**.
Владелец докладывает только замечания: молчание по блоку = «прошло».

Перед началом: закройте прошлые окна приложения (осиротевшие процессы Electron
дают «белый экран» — это не баг кода, см. MEMORY.md).

```bash
corepack pnpm dev
```

---

## Блок 1. Markdown в ответах (задача 1.6.4)

1. Спросите агента что-нибудь, на что он ответит списком и кодом — например:
   «Дай список из трёх пунктов и пример кода на python».
   ✓ Заголовки, списки и **жирный** видны как оформление, а не как `#`, `-`, `**`.
   ✓ Блок кода — в рамке, с подписью языка и кнопками копирования/скачивания,
     код подсвечен цветом.
   ✓ Пока ответ печатается, недописанная разметка не мигает звёздочками.

2. Переключите тему (шестерёнка → тема) и посмотрите тот же ответ.
   ✓ Читается в обеих темах; код меняет палитру вместе с темой.

## Блок 2. Ход рассуждений (задача 1.6.5)

3. Задайте вопрос, требующий рассуждения (например «сравни два варианта и
   объясни выбор»), дождитесь ответа.
   ✓ Карточка «Рассуждение» свёрнута, показывает две строки превью с
     многоточием.
   ✓ Разверните её: абзацы разделены, подзаголовки видны как заголовки,
     звёздочек `**` нет.

## Блок 3. Ссылки (задача 1.6.4a)

4. Попросите агента дать ссылку на любой сайт (например «дай ссылку на сайт
   ГОСТ»). Кликните по ссылке в ответе.
   ✓ Ссылка открылась **в вашем браузере**, окно приложения осталось на месте.
   ✓ Приложение не «ушло» на сайт и не открыло второе окно.

## Блок 4. Диагностика «карточки хода пропадают» (задача 1.6.2)

Это **сбор доказательства**, а не проверка. Дефект из вашего прогона 26.07 не
воспроизводится на модельном потоке событий (e2e-тест это проверяет), поэтому
нужен реальный поток.

5. Откройте консоль разработчика: **Ctrl+Shift+I** → вкладка Console.
6. Задайте вопрос, на который агент точно вызовет инструмент (например
   «прочитай файл X и перескажи»), дождитесь конца ответа.
   ✓ В консоли идут строки двух видов:
     `[aecpilot] evt tool.start #call_…` — поток событий шлюза;
     `[aecpilot] лента: сообщений N, инструментов N, рассуждений N` — что
     реально лежит в ленте после каждого изменения.
7. **Если карточки пропали с экрана** — посмотрите ПОСЛЕДНЮЮ строку «лента:».
   - Счётчики не упали (инструментов ≥ 1) → карточки на месте, их прячет
     представление (прокрутка/обрезка) — это одна причина.
   - Счётчики упали до нуля → их удаляет событие, которого мы не ждём; тогда
     нужны последние 10–15 строк `evt …` перед падением.

Пришлите скриншот или текст консоли — по нему причина определяется однозначно,
без гадания. Содержимого сообщений в логе нет (только типы событий и id
инструментов) — это правило секретов спеки.

## Блок 5. Выбор модели (задача 1.6.9)

8. В композере, слева от кнопки отправки, есть кнопка с названием модели.
   Нажмите её.
   ✓ Открылся список провайдеров и моделей.
   ✓ Провайдеры без ключа **видны, но не выбираются**, и рядом написано, чего
     не хватает (например «нужен ключ DEEPSEEK_API_KEY»). Это не ошибка — так и
     задумано: спрятанная модель выглядела бы как пропажа.
9. Выберите другую модель, дождитесь, пока надпись на кнопке сменится.
   ✓ На кнопке — новая модель. Она приходит от шлюза, а не от вашего клика:
     если надпись НЕ сменилась, значит переключение не состоялось, и это надо
     показать нам.
10. Задайте вопрос и, **пока идёт ответ**, нажмите кнопку модели.
    ✓ Написано «идёт ход — сначала остановите его», список моделей не активен.
      Их шлюз в этот момент переключение отклоняет; мы не даём получить ошибку.
11. Поменяйте «Глубину рассуждений» и «Быстрый режим».
    ✓ Подпись на кнопке дополняется выбранным (например «… · высокие · быстрый»).
    ✓ Если у модели нет быстрого режима, переключателя просто нет.

## Блок 6. Ссылки на файлы `@` (задача 1.6.A3)

12. Наберите в композере `посмотри @` (с пробелом перед собакой).
    ✓ Появился список: `@diff`, `@staged`, `@file:`, `@folder:`, `@url:`, `@git:`.
13. Продолжите набирать имя файла из вашего проекта, например `@main`.
    ✓ В списке — файлы **вашего проекта** (не чужой папки). Если список пуст
      или показывает посторонние файлы — это ошибка, сообщите.
14. Выберите файл стрелками и нажмите Enter, допишите вопрос и отправьте.
    ✓ Ссылка встала на место набранного, остальной текст цел.
    ✓ Агент отвечает **по содержимому файла** — раскрывает ссылку он сам.
15. Наберите почтовый адрес, например `пиши на ivan@example.com`.
    ✓ Никакого списка путей не появилось.

## Блок 7. Активная цель (задача 1.6.A5)

16. Отправьте `/goal собери список всех PDF в проекте` (или любую цель).
    ✓ Над композером появилась плашка «Цель активна N/20» с текстом цели.
    ✓ Агент продолжает работать **сам**, ход за ходом — и плашка объясняет,
      почему; счётчик ходов растёт.
17. Нажмите «Пауза».
    ✓ Плашка стала «Цель на паузе», появилась кнопка «Возобновить»,
      самостоятельные ходы прекратились.
18. Нажмите «Снять цель».
    ✓ Плашка исчезла полностью.

Если в плашке вместо понятной подписи видна английская строка целиком — это
значит, что шлюз ответил в формате, которого мы не знаем. Так и задумано
(лучше показать как есть, чем угадать), но пришлите нам эту строку.

## Блок 8. Вложения (задача 1.6.A4)

19. Нажмите скрепку слева от кнопки отправки, выберите картинку.
    ✓ Под композером появился чип с именем файла и крестиком.
20. Скопируйте любой скриншот (клавиша PrintScreen или Win+Shift+S) и нажмите
    Ctrl+V в поле ввода.
    ✓ Появился ещё один чип. Текст при этом не вставился — вставлялась картинка.
21. Напишите вопрос про приложенное и отправьте.
    ✓ Чипы исчезли (файлы ушли с сообщением), агент отвечает по картинке.
22. Нажмите скрепку и выберите **PDF**.
    ✓ Либо PDF принят и превратился в НЕСКОЛЬКО вложений — по одному на
      страницу (так устроен их шлюз: модель принимает картинки, не PDF);
    ✓ Либо появилось сообщение про poppler. **Это ожидаемо на Windows**: их
      обработчик вызывает системную утилиту `pdftoppm`, которой в Windows по
      умолчанию нет. Решение по установке poppler — за вами; отдельной задачей
      это не заводилось.
23. Нажмите крестик на чипе до отправки.
    ✓ Чип исчез, вложение снято.

## Блок 9. Экран отката (задача 1.6.C2)

**Перед прогоном:** этот блок зависит от нерешённого вопроса — класть ли маркер
(`.git`, `package.json`, …) в корень хранилища. Пока решения нет, экран, скорее
всего, покажет предупреждение, а не список. Это и надо проверить.

24. Откройте на рельсе активность «Агент».
    ✓ Виден раздел «Откат изменений».
25. Прочитайте, что написано вместо списка (или над ним).
    ✓ Если написано «Снимки не создаются вообще» — это ожидаемо и это ответ на
      вопрос про маркер: у вас в домашней директории есть `.git`, поиск дошёл
      до неё, и ядро отказалось снимать. **Снимков нет не потому, что агент
      ничего не менял.**
    ✓ Если написано «Чекпойнты собираются не для этой папки» — снимки уходят в
      названную директорию.
    ✓ Если список непустой — всё сошлось, идите дальше.
26. Только если список непустой: выберите снимок.
    ✓ Показаны файлы с пометками «изменён / добавлен / удалён» и сам патч,
      добавленные строки зелёные, удалённые красные.
27. Нажмите «Восстановить файл».
    ✓ Сначала спрашивают подтверждение и называют, ЧТО будет перезаписано.
      Ничего не восстанавливается до нажатия «Восстановить».
28. Подтвердите.
    ✓ Файл вернулся к состоянию снимка.
    ✓ Помните: файлы, созданные ПОСЛЕ снимка, откат не удаляет — это поведение
      ядра, а не наша недоработка (написано прямо в окне подтверждения).
