# AECPilot — дизайн-бриф для Claude Design

> Артефакт для генерации UI-дизайна. Поведение экранов канонично описано в `specs/*`
> и `SPECIFICATION.md`; этот бриф — их проекция на дизайн. При противоречии выигрывает
> SPECIFICATION. Версия: 2026-07-08 (решения владельца: правый чат-док · Linear-светлый
> визуал · высокая детализация всех экранов · hub «Агент» в рельсе).

## 0. Задание для Claude Design
Сгенерировать дизайн desktop-приложения (Electron, Windows-first, окно ≥1280×800):
1. Дизайн-токены: цвета (светлая + тёмная тема), типографика, отступы, радиусы, тени.
2. Макеты всех экранов из §5 в высокой детализации (light + dark, состояния из §6).
3. Компонентную библиотеку: кнопки, инпуты, дерево, табы, чипы цитат, пузыри чата,
   карточки approval, таблицы, тосты/баннеры, прогресс, модалки, командная палитра.
4. Ключевые потоки §7 как последовательности экранов.

## 1. Продукт и пользователи
**AECPilot** — «IDE для проектирования»: desktop-workspace инженера-проектировщика
(строительство/инжиниринг). Агент (ядро hermes-agent) отвечает на вопросы по исходным
данным проекта со ссылками на файл и страницу, ведёт вики проекта, готовит черновики
документов. Файлы — источник истины; серверов нет.

**Пользователь**: инженер-проектировщик, не программист. Уверенный пользователь Windows,
Word/Excel/AutoCAD; терминала не знает и знать не должен. Работает с большими PDF
(нормы, задания, сканы), DOCX, XLSX. Языки: русский и английский (UI en/ru).
Вторичный пользователь (позже): администратор, настраивающий агента под отдел.

**Два вида данных, всегда визуально различимы:**
- **Vault** — рабочая папка проекта (редактируемая): вики, черновики, шаблоны.
- **Источники** — подключённые read-only папки (сетевые/локальные): задания, нормы,
  чертежи. Агент и приложение НИКОГДА не пишут в источники (жёсткая гарантия N3).

## 2. Ментальная модель и визуальное направление
Модель — IDE (VS Code/Cursor), но для документов, не кода: слева навигация, в центре
документы, справа агент, снизу статус. «Language server» здесь — RAG с цитатами.

**Визуал: Linear-подобный светлый минимал** (решение владельца):
- Светлая тема по умолчанию + полноценная тёмная (переключатель + follow system).
- Спокойные нейтральные поверхности, тонкие границы (0.5–1px), без теней-украшений.
- Один акцентный цвет (интерактив, выделение, ссылки-цитаты) + семантические:
  success (connected, свежий индекс), warning (изменения, устаревший индекс,
  approvals), danger (недоступен, ошибки), muted (read-only, provenance).
- Плотность средняя: комфортно читать документы часами; компактнее Notion,
  просторнее VS Code. Списки/деревья ~28–32px строка.
- Типографика: системный UI-шрифт; моно — для путей, ID, tool-вызовов. Кегль основного
  текста ≥13px; в чате ≥14px.
- Ничего «терминального» в лексике UI: не «stdout», а «вывод инструмента».

## 3. Общий shell (одно окно)
```
┌────────────────────────────────────────────────────────────────────┐
│ Top bar: [проект ▾] [⌘K палитра] [scan now] [⚙ settings]           │
├──┬──────────────┬──────────────────────────────┬───────────────────┤
│Р │ Сайдбар      │ Центр: табы документов       │ Чат-док (правый)  │
│е │ (контекст    │ (вьюеры + MD-редактор)       │ сессии/стрим/     │
│л │ активности)  │                              │ approvals/цитаты  │
│ь │              ├──────────────────────────────┤                   │
│с │              │ Нижняя панель (сворачиваемая)│                   │
│а │              │ индексация · изменения · логи│                   │
├──┴──────────────┴──────────────────────────────┴───────────────────┤
│ Статус-бар: ●connected · модель · индекс · изменения(3) · RU/EN    │
└────────────────────────────────────────────────────────────────────┘
```
- **Рельса** (слева, ~44px, иконки+тултипы): Проводник · Q&A · Вики · Источники ·
  Память · Документы · **Агент** · (низ рельсы) Настройки.
- **Сайдбар** (~240–320px, resize, collapse): содержимое зависит от активности.
- **Центр**: табы документов (закрытие, средняя кнопка, dirty-точка у MD), drag-reorder,
  split не в v1. Пустое состояние центра — подсказки «открой файл / спроси агента».
- **Чат-док** (справа, ~320–420px, resize, collapse в иконку): постоянен во всех
  активностях. Кнопка «развернуть» (чат на весь центр) — предусмотреть место, v1 опц.
- **Нижняя панель**: вкладки «Индексация», «Изменения», «Журнал»; сворачивается в
  строку статус-бара.
- **Статус-бар**: состояние gateway (●connected/reconnecting/disconnected), активная
  модель, **режим одобрений** (manual/smart/off — индикатор; клик открывает поповер
  выбора режима; off — предупреждающая окраска), статус индекса (свежий/устаревший/
  идёт ingest), счётчик изменений источников (клик → нижняя панель «Изменения»), язык UI.

## 4. Навигация
- Активность в рельсе меняет сайдбар; центр и чат-док сохраняются.
- **Командная палитра** (Ctrl/Cmd+K): файлы vault и источников по имени, команды
  («Сканировать сейчас», «Обновить вики», «Новая сессия», «Собрать документ»),
  переключение проектов/сессий.
- Клавиатура: Ctrl+P файлы, Ctrl+K команды, Ctrl+Enter отправить в чат, Esc закрыть
  модалку/палитру, F2 rename в vault-дереве.
- Все деревья/списки — единый компонент (виртуализация, react-arborist).

## 5. Экраны

### 5.1 Welcome / выбор проекта
Показ при старте без открытого проекта. Центрированная карточка: логотип, «Создать
проект» (выбор пустой папки → генерация структуры vault → открытие), «Открыть проект»
(выбор папки с `.aecpilot/`), список недавних (имя, путь, дата; pin; удаление из
списка). Ошибки: папка не пуста (создание), нет `.aecpilot/` (открытие), нет прав.
Файл проекта отсутствует на диске → строка недавних приглушена с пометкой.

### 5.2 Проводник (сайдбар активности 1)
Две секции одного дерева-паттерна:
- **Vault** (редактируемый): папки/файлы; создание, переименование (F2, инлайн),
  удаление (с подтверждением), drag-перемещение. MD-файлы открываются в редакторе,
  остальные — во вьюерах.
- **Источники** (read-only): каждый источник — корень с бейджем `RO` и именем;
  **разворачивается вглубь на любую глубину как обычное дерево**. Статусы корня:
  ok · «недоступен» (danger-иконка, поддерево не грузится, остальное работает) ·
  «отключён» (пометка detached). Файлы открываются во вьюерах (только чтение).
- **Контекстное меню любого узла**: «Показать в проводнике» (системный файловый
  менеджер, файл подсвечен), «Копировать путь»; для файлов — «Открыть во внешнем
  приложении»; для vault дополнительно — создать/переименовать/удалить.
- Поиск по дереву (фильтр по имени, подсветка совпадений).
- Пустые состояния: «vault пуст» (кнопка создать файл), «нет источников» (кнопка
  добавить → 5.3).

### 5.3 Источники (активность 4, менеджер)
Список подключённых источников карточками/строками: имя, полный путь (моно),
статус (ok/недоступен), счётчики (файлов, проиндексировано, устарело), дата
последнего скана. Действия: «Добавить источник» (диалог выбора папки + валидации:
источник внутри vault / vault внутри источника — запрещено; пересечение путей двух
источников — предупреждение), «Отключить» (подтверждение + пояснение: записи индекса
помечаются detached, страницы вики останутся с пометкой), «Показать в проводнике»,
«Сканировать сейчас» (точечно). Настройка интервала сканирования — ссылка в Settings.

### 5.4 Q&A (активность 2)
Сайдбар: строка запроса + история запросов. Результаты (в сайдбаре или центр-табе
«Результаты поиска»): два режима — «Семантический» (RAG) и «Точный» (FTS5), переключатель.
Каждый результат: сниппет с подсветкой, файл (имя+путь), страница/локатор, кнопка
«Открыть» (центр-таб на нужном месте) и «Спросить агента об этом» (подставляет в чат).
Состояния: индекс пуст (CTA «Запустить ingest»), индекс устарел (warning-баннер
«N файлов изменилось — результаты могут быть неполными», кнопка re-ingest), «ничего
не найдено» (честное пустое состояние). Это UI-обёртка над `rag_query`
(specs/qa-over-sources.md); основной сценарий вопросов — всё же чат.

### 5.5 Вьюеры и MD-редактор (центр)
Общее: каждый документ — таб (иконка формата, имя, dirty-точка у MD). Верхняя
панель вьюера: имя файла, путь (тултип), «Показать в проводнике», «Открыть во
внешнем приложении», зум (для PDF), поиск по документу (Ctrl+F).
- **PDF** (pdfjs): постраничный скролл, миниатюры (сворачиваемые), зум, поиск по
  тексту, переход к странице; **открытие по цитате — прыжок на страницу с
  краткой подсветкой-вспышкой**. Скан без текстового слоя — работает как картинка,
  бейдж «скан». Битый файл — понятная ошибка в табе, не падение (AC8).
- **DOCX** (docx-preview): read-only рендер, поиск; открытие по локатору-заголовку
  (решение O4, Phase 2) — прыжок к заголовку.
- **XLSX/CSV** (Univer, read-only): листы табами, заморозка шапки, выделение
  диапазона из локатора цитаты; большой файл — прогресс загрузки.
- **TXT**: просмотр с переносами, моно-опция.
- **MD-редактор** (Milkdown, WYSIWYG): для файлов vault и вики; автосохранение,
  undo; `[[wikilinks]]`: клик — переход, несуществующая страница — создание по
  клику (подтверждение); ссылки на источники из вики (провенанс) — кликабельны и
  открывают вьюер на месте.

### 5.6 Вики (активность 3)
Сайдбар: дерево страниц вики (wiki/), статус staleness (страница ссылается на
изменённый источник — warning-метка), кнопка «Построить вики» / «Обновить вики»
(запуск через агента, с подтверждением; прогресс в нижней панели).
Центр: страница вики в MD-редакторе. Особые блоки, которые надо задизайнить:
- **Провенанс-блок**: «источник: <файл, страница>» — muted-чип под заголовком/абзацем,
  клик открывает источник.
- **Блок противоречия**: явно выделенный блок «Противоречие: <вариант А (источник)>
  vs <вариант Б (источник)>» — warning-стилистика, не теряется при чтении.
- **Lint-отчёт вики** (центр-таб): список находок (битые ссылки, сироты, staleness,
  незакрытые противоречия) со статусами и переходами к странице.
Ручная правка страниц сохраняется при обновлении (аддитивность — specs/wiki.md).

### 5.7 Изменения источников (нижняя панель · вкладка «Изменения» + тост)
Детект по расписанию (sha256). При находке: ненавязчивый тост + счётчик в статус-баре.
Вкладка: таблица изменений (файл, источник, тип: добавлен/изменён/удалён, когда
замечено), группировка по источнику, чекбоксы. Действия над выбранным: «Re-ingest»,
«Обновить вики» (доступно с Phase 3). **Ничего не выполняется без явного
подтверждения** (AC5) — кнопки ведут на подтверждающий диалог со сводкой.

### 5.8 Индексация (нижняя панель · вкладка «Индексация»)
Прогресс текущего ingest (файл N из M, этап: парсинг/OCR/чанки/эмбеддинг, отмена),
сводка индекса (всего файлов, проиндексировано, устарело, размер), история прогонов
(журнал: когда, сколько, ошибки по файлам — файл открываем кликом). Ошибки отдельных
файлов не валят прогон — собираются списком.

### 5.9 Чат-док (правый, постоянный)
Шапка: селектор сессии (имя/автоимя, дропдаун: список, поиск, «Новая сессия»),
индикатор соединения, меню сессии (переименовать, ветка/branch, компрессия контекста,
usage, закрыть). Тело — лента:
- **Пользователь**: выровнен вправо, акцентная заливка.
- **Ассистент**: слева, стриминг с курсором-миганием; markdown-рендер (списки,
  таблицы, код); **чипы цитат `[src: файл, стр. N]`** — компактные кликабельные
  чипы в тексте, клик открывает вьюер на месте; невалидная цитата — чип с
  предупреждением.
- **Thinking/reasoning**: сворачиваемая muted-полоска «думает…» (по клику —
  развернуть текст размышлений).
- **Tool-вызов**: компактная карточка «⚙ имя_инструмента (аргументы кратко)» →
  статус (running/ok/error) → сворачиваемый вывод (моно, обрезка длинного с
  «показать всё»). Группа подряд идущих вызовов сворачивается в стопку.
- **Субагенты**: вложенная карточка «подзадача: <название>» со своим мини-стримом
  (текст/инструменты), статус start/complete.
- **Approval-карточка** (approval.request): warning-стилистика, заголовок «Агент
  запрашивает разрешение», описание действия (что/куда/зачем — как diff-сводка),
  кнопки Approve / Deny (+ «всегда для этой сессии» — чекбокс, если поддержано).
  Блокирует ввод до ответа. Аналогичные карточки: **clarify.request** (вопрос с
  вариантами/полем), **secret.request** (поле ввода секрета, маскирование, «не
  сохранять в истории»), **sudo.request** (усиленный warning).
- **status.update**: тонкая строка статуса между сообщениями (retry, rate-limit).
- Ошибка модели (message.complete status=error): карточка ошибки с человекочитаемым
  текстом и кнопкой «повторить».
Низ: многострочный ввод (авторост до ~6 строк), Enter — отправить, Shift+Enter —
перенос; кнопка Stop (session.interrupt) во время стрима; кнопка вложения
(файл/изображение/PDF — gateway поддерживает; в v1 место зарезервировать, функция
Phase 2+); счётчик контекста сессии (usage) — muted в углу.
Пустая сессия: подсказки-примеры вопросов по проекту.

### 5.10 Агент (активность 7 — hub возможностей hermes)
Сайдбар: разделы hub'а. Центр — контент раздела:
- **Персона**: редактор SOUL.md (MD-редактор) + пояснение «влияет на стиль и язык
  агента»; предупреждение о перезапуске сессии для применения.
- **Скиллы** (skills.manage/reload): список карточками (имя, описание, версия,
  источник: встроенный aec-* / пользовательский), тумблер вкл/выкл, «Установить»
  (из папки; из URL — позже), «Перезагрузить скиллы». Бейдж «эталонный» у aec-qa.
- **MCP-серверы** (config + reload.mcp): список (имя, команда/транспорт, статус
  running/error, кол-во инструментов), добавить/редактировать (форма: имя, команда,
  аргументы, env — секретные значения маскируются), удалить (подтверждение),
  «Перезагрузить MCP». Наши aec-sources/aec-rag/aec-memory — с бейджем «встроенный»,
  их удаление запрещено (только вкл/выкл).
- **Инструменты** (tools.list/configure, toolsets.list): справочный список
  инструментов агента, группировка по toolset, вкл/выкл где поддержано.
- **Cron и хуки** (cron.manage + файлы hooks/): вкладка «продвинутое»; список
  задач/хуков, редактирование как текст; предупреждение N7 (автономные LLM-задачи
  не в MVP — интерфейс read-only + disable в v1).
- **Журнал сессий** (session.list/history/usage): таблица всех сессий (название,
  создана, сообщений, токены/стоимость), действия: открыть в чат-доке (resume),
  ветка (branch), компрессия, удалить; экран истории выбранной сессии (read-only
  лента как в чат-доке). Rollback (rollback.list/diff/restore) — в деталях сессии,
  «продвинутое», с diff-просмотром и подтверждением restore.

### 5.11 Память (активность 5)
Вкладки скоупов: «Пользователь» и «Проект» (Mem0; specs/agent-memory.md).
Список записей: текст факта, когда создана, источник (авто/вручную), поиск по
записям; удаление записи (подтверждение); массовое удаление. Тумблер «Автозапись»
(вкл/выкл; пояснение про фильтр секретов). Пустое состояние: «память пуста —
агент начнёт запоминать факты по мере работы».

### 5.12 Документы (активность 6 — docgen)
Мастер генерации (specs/docgen.md; в MVP — пояснительная записка):
1. Выбор шаблона (карточки из templates/ с manifest.yaml: имя, описание, поля).
2. Запуск сбора данных агентом (прогресс, лог этапов).
3. **Ревью черновика**: центр — превью DOCX; панель полей: каждое поле — значение,
   статус (найдено/`НЕ НАЙДЕНО` — warning), провенанс-ссылка на источник (клик —
   вьюер), конфликтные значения — блок выбора варианта.
4. Сохранение в workspace/drafts/ + отчёт report.md (открывается табом).
Список ранее собранных черновиков (drafts/): имя, шаблон, дата, статус ревью.

### 5.13 Настройки (модал или центр-таб; разделы слева)
- **LLM**: провайдер/endpoint (OpenAI-совместимый), модель (model.options),
  API-ключ (маскированный инпут, хранение в safeStorage, «ключ никогда не пишется
  в открытые файлы»), кнопка «Проверить соединение» (llm-пинг), reasoning effort.
- **Эмбеддинги**: модель эмбеддингов; предупреждение C5 — «смена = полный re-ingest»
  (подтверждающий диалог с оценкой объёма).
- **Языки**: язык UI (en/ru), язык вики проекта (auto/явный), язык агента (правило
  в SOUL — ссылка на Персону).
- **Одобрения**: режим работы агента — `manual` (человек одобряет рискованные
  действия; дефолт), `smart` (LLM авто-решает), `off` (без одобрений; явное
  предупреждение об ответственности). Дублирует поповер статус-бара; применяется
  без перезапуска.
- **Сканирование**: интервал детекта изменений, лимит размера файла.
- **Внешний вид**: тема (light/dark/system), плотность (после MVP — зарезервировать).
- **О программе**: версии (app, hermes-agent pinned, Python), пути профиля,
  диагностика (статус gateway, кнопка «перезапустить агента», логи).

### 5.14 Командная палитра (Ctrl+K)
Оверлей по центру сверху: инпут + список результатов с группами (Файлы · Команды ·
Сессии · Страницы вики), клавиатурная навигация, подсветка совпадений, недавние.

## 6. Сквозные состояния
- **Соединение с агентом**: connected (тихо, зелёная точка) · connecting/reconnecting
  (жёлтая, спиннер в чат-доке) · disconnected (баннер в чат-доке: «Агент недоступен»
  + кнопка «Переподключить»/«Перезапустить», ввод выключен; остальное приложение
  работает — вьюеры/дерево не зависят от агента).
- **Индекс**: свежий · устарел (warning в статус-баре + баннер в Q&A) · идёт ingest
  (прогресс в статус-баре) · пуст (CTA в Q&A и чате).
- **Пустые состояния** каждого экрана — с одним понятным действием (см. §5).
- **Ошибки**: человекочитаемо, без стектрейсов; «подробности» — сворачиваемо;
  ключи/секреты в текстах ошибок всегда замаскированы.
- **Длинные операции** (ingest, построение вики, сбор документа): прогресс в нижней
  панели + ненавязчивый тост по завершении; отменяемость где возможна.

## 7. Ключевые потоки (задизайнить последовательностями)
1. **Первый запуск**: Welcome → создать проект → пустой workspace с подсказками →
   добавить источник → предложение запустить ingest → прогресс → готово.
2. **Вопрос → цитата → источник** (эталон G1): вопрос в чат-доке → стрим ответа с
   tool-карточкой rag_query → чип цитаты → клик → PDF-таб на нужной странице с
   подсветкой.
3. **Изменение источника**: тост «3 файла изменились» → нижняя панель → выбор →
   Re-ingest (подтверждение) → прогресс → индекс свежий; (Phase 3) «Обновить вики».
4. **Approval**: агент хочет записать черновик в workspace/ → approval-карточка в
   чате (что/куда) → Approve → tool-карточка выполнена → файл виден в дереве.
5. **Построить вики**: активность Вики → «Построить» → подтверждение → прогресс →
   дерево страниц заполнено → страница с провенанс-чипами и блоком противоречия.
6. **Собрать пояснительную записку**: Документы → шаблон → сбор (прогресс) → ревью
   полей (НЕ НАЙДЕНО + конфликт) → сохранить в drafts/ → отчёт.

## 9. Компонентно-технические ограничения
- Electron 43 + React 19 + TypeScript; сборка electron-vite; стили — без тяжёлых
  UI-фреймворков (дизайн-токены → CSS-переменные; допустима лёгкая headless-база).
- Готовые компоненты, под которые рисуем: **react-arborist** (деревья),
  **Milkdown** (MD-редактор), **pdfjs-dist** (PDF), **docx-preview** (DOCX),
  **@univerjs** (таблицы), **i18next** (en/ru).
- Один чат-движок уже реализован (стрим-события gateway → reducer) — дизайн ленты
  должен лечь на существующие события (5.9 = их визуализация).
- Иконки: один консистентный outline-набор (Lucide или аналог — permissive-лицензия).
- Виртуализация длинных списков (дерево, лента чата, результаты, журнал).

## 10. Локализация и доступность
- UI en/ru; русские строки длиннее английских на ~20–30% — макеты не должны ломаться.
- Даты/числа по локали. Пути всегда LTR-моно.
- Контраст WCAG AA в обеих темах; фокус-кольца на всех интерактивах; полная
  клавиатурная навигация (деревья, палитра, чат, approvals — Approve/Deny с
  клавиатуры); aria-метки на иконках-кнопках.
