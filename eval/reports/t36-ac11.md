# T36 — приёмка AC11: сервер и клиент двумя установками на одной машине

Дата: 2026-10-21. Сборка: установщик `AECPilot-0.1.0-win-x64.exe` от 2026-10-21 (коммит `ffed1d9`, T35.2).
Спека: `apps/desktop/e2e/acceptance/ac11-server-client.spec.ts`, проект Playwright `clean-machine`.

## Установки

- Сервер — `D:\AECPilot-cleantest\server`, установщиком `/S /MODE=server`. Повторный запуск установщика поверх
  — обновление: 1952 с, `install-mode.txt` остался `server`, задача «AECPilot Server» на месте
  (`AECPilot.exe --server`, триггер входа пользователя). Запуск задачи (`schtasks /Run`, как при входе):
  шлюз слушает только `127.0.0.1:18789`, окон у процессов сервера — 0; после остановки порт свободен.
- Клиент — `D:\AECPilot-cleantest\client`: та же сборка без `runtime\core` и `runtime\mcp`, `install-mode.txt` = `client`
  (один appId: второй запуск установщика обновил бы первую установку).

## Прогон

Один полный прогон, 8/8, 9,2 мин (живая модель — Gemini, профиль автотестов, ключ задан окном сервера):

| Шаг | Что доказано |
|---|---|
| AC11.1 | сервер без окна, шлюз только на 127.0.0.1, токен постоянный и хранится зашифрованным |
| AC11.1а | ключ модели задан окном «Ключи моделей» на сервере (T35.2); из `.env` копии профиля ключи стёрты, значения нет в окне, поле стёрто, ядро перезапущено |
| AC11.2 | клиент без своего ядра подключается к шлюзу сервера; токен открытым текстом не лежит в настройках клиента |
| AC11.3 | проект открывается с клиента на диске сервера (`server-state.json`) |
| AC11.4 | два источника подключены с клиента, индексацию сделал сервер (T35.1) |
| AC11.5 | ответ со ссылкой `[src: …/отчёт.pdf#p7]` и дословной цитатой; щелчок открывает PDF сервера на стр. 7 из 17 |
| AC11.6 | `.aecpilot` (index.db, lightrag, server-state.json) — только у сервера; ядро и наши MCP — только у сервера; у клиента следов индекса нет (кроме шаблона демо-проекта из поставки — один `project.json`) |
| AC11.7 | клиент закрыт — сервер сам просканировал источник и увидел новый файл |

## Что не входит

- Перезагрузка машины не выполнялась: вход пользователя имитирован запуском задачи (`schtasks /Run`).
- Обрыв связи с сервером (T35) — отдельной бесплатной спекой `ac11-connection-break.spec.ts` (профиль без ключа):
  при остановленном сервере клиент в состоянии `reconnecting`, в поле ввода «Переподключение к AECPilot…», в строке
  состояния «Бэкенд подключение»; после подъёма сервера связь вернулась сама. 1/1, 2,3 мин.

  проверка AC11.6 приняла шаблон демо-проекта из поставки за след индекса — исправлена.
