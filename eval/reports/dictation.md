# Замер диктовки (T58), 2026-11-24

Вопрос: годится ли местное распознавание речи ядра (faster-whisper) для инженерной диктовки и
какую модель брать по умолчанию.

## Как мерили

- 10 записей владельца (`eval/samples/dictation`, в git не попадают), 74 с речи, эталон —
  `eval/dictation-phrases.md`. Стенд — `eval/dictation_bench.py`: распознаёт **код ядра**
  (`tools.voice_mode.transcribe_recording`) с `stt.provider: local`, `stt.language: ru`;
  параметры — умолчания ядра (beam 5, VAD, без контекста прошлого куска).
- Процессор i7-12650H, int8, без видеокарты, без сети. Бесплатно.
- **Верно терминов** — сколько из 49 терминов, чисел и обозначений записаны так, что править не
  надо. **WER** — доля слов с ошибкой.
- **Повторы.** При умолчаниях ядра текст повторяется дословно. С явно заданным числом потоков
  (4 или 8) та же модель пишет немного иначе: medium — 36–39 терминов (WER 28–30 %), small со
  словарём — 37–38 (30–34 %), small — 33–34 (32–38 %), turbo — 40–41 (23–24 %). Причину не
  разбирали; разница в один-два термина ничего не доказывает, на другой машине числа могут
  сдвинуться. Turbo со словарём — один прогон.
- «Словарь» — подсказка ядра `stt.local.initial_prompt` с общими терминами КР
  (`eval/dictation-vocabulary.txt`). Часть её слов есть и в
  фразах замера (КЖ, КМ, А500С, А240, РСУ, кПа, продавливание, диафрагма жёсткости), поэтому
  прибавка от словаря скорее завышена.

## Почему бывает вчетверо медленнее

В части прогонов всё шло вчетверо дольше. Раньше здесь стояло «машина занята» — это не
подтвердилось: посторонней нагрузки не хватало, нагрев скорость не ограничивал. У i7-12650H шесть
быстрых и четыре энергосберегающих ядра, и Windows 11 переводит процесс без окна на медленные.
Проверено на turbo, один и тот же текст во всех прогонах, секунд на фразу:

| Как запущено | Секунд на фразу |
|---|---|
| как есть, без окна (два прогона) | 32 и 38 |
| принудительно на энергосберегающих ядрах | 28 |
| приоритет выше обычного | 19 |
| принудительно на быстрых ядрах | 10 |
| процесс просит у Windows полную скорость (`SetProcessInformation`, отказ от энергосбережения) — два прогона | 9,0 и 7,7 |
| то же, medium | 5,7 |

Шлюз ядра — тоже процесс без окна, поэтому в программе возможно то же самое. Там это **не
проверено**; если подтвердится, программа должна просить у Windows полную скорость для шлюза.

## Что видно по тексту

- medium пишет обычные фразы почти без правки: «Найди в разделе КЖ узел сопряжения монолитной
  стены с плитой перекрытия», «Защитный слой бетона для фундаментной плиты принять 50 миллиметров».
- **Тихая ошибка в нагрузке.** В одном из прогонов medium (4 потока) вместо «временная 2 кПа»
  написала «временная **2,5 кПа**»: число правдоподобное, на глаз не отличить. В трёх из
  четырёх её прогонов без словаря коэффициент надёжности получил лишнее «кПа». Другие опасные
  замены: «шаг двести» → «2», «F150» → «в 150» (small), «отметка плюс двенадцать шестьсот» → «по 9600» (small).
- **turbo** вернее всех по словам: «Проверь прогибы балки Б3 по СП-63 при пролете 6 метров»,
  «марка … по водонепроницаемости W6», «хомуты из А240 диаметром 8» (medium это искажает).
  Нагрузки (4,5 и 2) верны во всех прогонах. Её слабые места: F150 без словаря потеряна в двух
  настройках из трёх («в 150» при умолчаниях, «150» при 8 потоках), «кП» вместо «кПа»
  при умолчаниях, «шаг двести» → «шагов», в одном прогоне «Формирование» вместо «Армирование».
- Ни в одном прогоне не записано как в эталоне: «плюс двенадцать шестьсот» (medium пишет 12600),
  «шаг двести» (пишет 2), «балки Б-3 по СП 63.13330» (слипается), «в осях А–В / 1–4», «по двутавру 30Б1». Часть из
  этого может быть особенностью записи: проверить это без владельца нельзя.
- **Словарь опасен обозначениями.** В нём был «двутавр 20Ш1» — и обе модели вместо «30Б1»
  написали «30Ш1»: правдоподобное, но неверное сечение. Без словаря ошибка хотя бы заметна
  («30%», «Ру-30»). Если словарь брать, то без обозначений. У medium он пользы не даёт.

## Вывод

Местное распознавание годится как черновик: текст встаёт в поле, человек читает его перед
отправкой; числа и обозначения проверять обязательно. По умолчанию предлагаю **large-v3-turbo без
словаря**: по терминам 40–41 против 36–39 у medium, по словам 23–24 % ошибок против 28–30 %, и
разброс прогонов не перекрывается. Размер и память почти как у medium, ожидание 7–9 с против 5–6 с.
Если важнее скорость — medium, ещё быстрее и проще — small (33–34, 2 с). base не годится.

Границы замера: один голос, 10 записей, 74 с речи. Видеокарта не мерилась (нужны библиотеки
NVIDIA, в поставку не входят). Модель: `dropbox-dash/faster-whisper-large-v3-turbo`, MIT, ревизия
`0a363e9161cbc7ed1431c9597a8ceaf0c4f78fcf` (репозиторий переименован из `mobiuslabsgmbh`, который
указан в faster-whisper; суммы файлов совпали).
