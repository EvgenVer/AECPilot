# Сколько стоит граф — замер на одном документе (задача 2.9a)

**Дата:** 2026-08-15 · **Модель извлечения:** `gpt-5.4-mini-2026-03-17` ·
**Раннер:** `uv run python eval/graph_cost.py --run --max-chunks 40`

SPECIFICATION R6 говорит, что построение графа стоит вызова LLM на каждый чанк.
Задача 2.9a требует превратить это предложение в числа **до** любого полного
прогона: если один документ окажется непристойно дорог, менять придётся схему
(UR24), а не интерфейс выбора.

## Что мерялось

Документ — `ТЗ на разработку РД 2-я очередь. ЖК 1-й Нагатинский (верс.4)`,
4,5 МБ DOCX из `eval/samples/project/`. Это настоящий проектный документ, а не
фикстура.

| Величина | Значение |
|---|---|
| Разбор Docling | 99 с |
| Сегментов (заголовков) | 1 |
| Чанков во всём документе | **288** |
| Взято в замер | 40 чанков (43 310 токенов текста) |

Замер идёт через **настоящий конвейер** LightRAG на наших чанках
(`aec_rag.lightrag_bridge`), а не через воспроизведённый промпт: считается то,
что реально уходит в модель.

## Результат

| Величина | На 40 чанков | На чанк |
|---|---|---|
| Вызовов модели | 81 | **2,02** |
| Входных токенов | 260 682 | **6 517** |
| Выходных токенов | 38 548 | **964** |
| Время | 78,7 с | 1,97 с |
| Сущностей найдено | 339 | 8,5 |
| Связей найдено | 328 | 8,2 |

**Два вызова на чанк, а не один.** Умолчание LightRAG —
`entity_extract_max_gleaning = 1`: после первого извлечения он повторяет запрос
«что ещё осталось» с историей первого ответа в контексте. Второй вызов дороже
первого по входу (в нём лежит первый ответ целиком). Отключение gleaning
уменьшило бы счёт примерно вдвое ценой полноты графа — решение отложено до
эвала 2.17, где полноту можно будет измерить, а не предполагать.

**6 517 входных токенов на чанк при 1 083 токенах самого текста.** Шесть седьмых
входа — это промпт извлечения (роль, типы сущностей, разделители, примеры) плюс
история для gleaning. Отсюда прямое следствие: **чанки меньше нынешних 2000
символов увеличивают стоимость почти линейно**, потому что промпт платится за
каждый чанк заново.

## Проекция

| Объём | Входных токенов | Выходных | Время |
|---|---|---|---|
| Этот документ целиком (288 чанков) | 1 877 000 | 278 000 | ~9,5 мин |
| Эталонный проект (464 чанка, PLAN §Architecture) | **3 024 000** | **447 000** | **~15 мин** |

Деньги в отчёте не проставлены намеренно: прайс `gpt-5.4-mini-2026-03-17` — факт
аккаунта владельца, а не наш, и выдуманное число здесь было бы хуже отсутствия
числа. Формула:

```
стоимость = 3,02 · цена_входа($/1M) + 0,45 · цена_выхода($/1M)
```

Для ориентира: при mini-тарифе порядка $0,25/1M входа и $2/1M выхода эталонный
проект стоит около **$1,7**, и это разовый расход — граф не перестраивается,
пока документы не менялись. При тарифе на порядок выше — около $17, и тогда
разговор о gleaning становится предметным.

## Выводы для проекта

1. **Граф на эталонном проекте — не запретительно дорог.** Порядок величины —
   единицы долларов и четверть часа, а не сотни долларов и ночь. Схема UR24
   (граф по выбору, а не по умолчанию) остаётся правильной, но по причине
   «не платить за то, чего не спрашивали», а не «иначе разоримся».
2. **Дорого — не построение, а перестроение.** 15 минут на проект означает, что
   молчаливое добавление новых файлов в отмеченную папку недопустимо не только
   по деньгам: человек, нажавший «добавить папку» полгода назад, получит
   четвертьчасовой прогон в момент, который выберет не он. Требование UR24
   «спросить, показав число документов и оценку» подтверждено замером.
3. **Оценка объёма перед запуском обязана считать чанки, а не файлы.** Один
   DOCX дал 288 чанков — больше, чем иной десяток PDF. `rag_graph_add` возвращает
   `chunks_estimate` из `ingested_files`, то есть настоящее число, а не догадку.

## Что этот замер нашёл по дороге

Три дефекта, каждый из которых — тихая потеря данных, и ни один не был бы виден
на тестах со стабами:

1. **Таблица длиннее окна эмбеддингов.** ТЗ Docling отдаёт одной таблицей на
   ~150 000 токенов. Правило «таблицу не режем никогда» давало чанк, который
   LightRAG молча резал сам по границе токенов, переименовывая куски (`…-s12`) —
   и вместе с именем терялся locator. Чанкер теперь режет большую таблицу по
   строкам, повторяя шапку.
2. **`openai_embed` — задекорированная `EmbeddingFunc` с шириной 1536.** Вызов
   её как функции из нашей `EmbeddingFunc` — то самое двойное декорирование, от
   которого предупреждает их собственная документация: любой настоящий ingest
   падал с «expected 10 vectors but got 20». Лечится вызовом `.func`.
3. **Дедупликация документов по basename и по содержимому + глобальное на
   процесс состояние.** Разобрано в коммите ingest'а; коротко — `ЭОМ/Задание.pdf`
   и `ОВ/Задание.pdf` считались одним документом.

## Как повторить

```bash
uv run python eval/graph_cost.py --run --max-chunks 40 --json eval/reports/graph-cost-live.json
```

Без `--run` тот же прогон бесплатен: конвейер настоящий, модель заменена
счётчиком, и точное число **входных** токенов получается без единого обращения к
API. Ключ берётся из окружения процесса или из `--env-file`; в отчёт он не
попадает никогда.

**Оговорка об объёме.** Мерялись 40 чанков из 288, то есть проекция линейна по
построению. Нелинейность здесь есть и работает в нашу пользу: чем больше
документ, тем чаще сущности повторяются и тем чаще срабатывает слияние описаний
(`force_llm_summary_on_merge = 8`), которое добавляет свои вызовы. На 40 чанках
слияний почти не было — значит, проекция скорее занижена, чем завышена. Уточнить
на полном прогоне эталонного проекта (2.18).
